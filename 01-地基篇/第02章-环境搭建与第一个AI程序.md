**为什么用 `openai` SDK 而不是每家一个 SDK**：OpenAI 的 Chat Completions 格式已是行业事实标准——DeepSeek、智谱 GLM、Kimi、Gemini（官方兼容层）、OpenRouter 全部兼容。**一套代码 + 切换 baseURL**，这就是本课程「三件套」方案的由来。

### 换厂商的边界（2026-11 复核）

「只改 baseURL」对国内兼容厂商完全成立，但对两家国际大厂的新模型只部分成立。先知道边界在哪，后面换模型时才不会被奇怪的 400 绊倒：

| 目标 | 能不能「只改三件套」 | 要注意什么 |
|---|---|---|
| DeepSeek / GLM / Kimi / Gemini 兼容层 / OpenRouter | ✅ 能 | `max_tokens`、`temperature` 都是标准参数，行为不变——**课程主线就走这条路** |
| OpenAI 原生 · GPT-6 系 | ⚠️ 部分 | 参数名要换成 `max_completion_tokens`；推理强度不是 `none` 时必须去掉 `temperature`/`top_p`，否则报错；**GPT-6 Astra / 6.1 Sol / 6.1 Terra 的工具调用只在 Responses API 上可用**，Chat Completions 不行（第 7 章再讲）。OpenAI 官方的说法是 Chat Completions 继续支持，新项目推荐 Responses |
| Anthropic · Claude | ⚠️ 部分 | 正式用法是自家 Messages API：`@anthropic-ai/sdk` ≥1.0 默认的 API 版本 2026-10-21 已不接受 `temperature`/`top_p`/`top_k`（带了就 400）。Anthropic 也提供官方 OpenAI 兼容端点（`baseURL: https://api.anthropic.com/v1/`），但限制多：Claude 4.7 及以后的模型 `temperature` 小于 1 直接 400；`response_format` 只收 `json_schema` + `strict`（`json_object` 会 400）；Opus 5.5 / Sonnet 5.5 / Fable 系不支持强制 `tool_choice`；不支持 prompt 缓存（第 17 章讲缓存时单独处理） |

所以本章的封装有两个刻意设计：**`temperature` 只在你显式传入时才发送**（换到 GPT-6 / Claude 新 API 时不传就行），以及**所有模型信息走环境变量**。

## 2.4 项目初始化

```powershell
mkdir hello-llm && cd hello-llm
pnpm init                                    # pnpm 12 生成的 package.json 自带 "type": "module"
pnpm add openai dotenv zod
pnpm add -D typescript tsx @types/node@24    # 用 Node 26 就写 @types/node@26
pnpm approve-builds esbuild                  # 上一行会报 ERR_PNPM_IGNORED_BUILDS，放行 esbuild 后即可用
```

> 上面第 4 行报错时依赖其实已经装上了，只是 esbuild 的构建脚本被拦着没跑；执行第 5 行后，pnpm 会补跑这个脚本，并生成 `pnpm-workspace.yaml`（记得提交进 Git，见 2.2）。

**`"type": "module"` 必须有**：本课程所有项目都是 ESM——Vercel AI SDK v7 只发布 ESM 版本，顶层 `await` 也只能在 ESM 里用。`pnpm init` 已经替你写好；如果你的 `package.json` 是别的方式生成的，手动加上 `"type": "module"`。

然后在根目录新建 `tsconfig.json`。**编译选项与配套代码 `code/tsconfig.json` 完全一致**，只有 `include` 不同（`code/` 的文件放在 `src/`、`test/` 两个目录里，`hello-llm` 的文件直接放在项目根目录）：

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2024",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2024"],
    "types": ["node"],
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": false,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["**/*.ts"]          // code/tsconfig.json 里是 ["src", "test"]
}
```

再在 `package.json` 的 `"scripts"` 里加一行类型检查命令（第 6 章「四道防线」的第一道就是它）：

```json
"scripts": {
  "typecheck": "tsc --noEmit"
}
```

这份配置每一行都有原因：

- **`noEmit` + `moduleResolution: "bundler"`**：本课程用 `tsx` 直接运行 TS，`tsc` 只做类型检查、不产出 JS。在这个组合下，相对导入可以不写扩展名（`import { chat } from "./lib/ai"`），全课程都这么写。如果你照网上教程写成 `"module": "NodeNext"`，`pnpm typecheck` 会要求所有相对导入都写 `.js` 扩展名，后面各章代码会一片红。
- **`"types": ["node"]`**：TypeScript 7 起 `types` 的默认值就是 `[]`（不再自动加载 `@types/*`），不写这一行会报 `process` 未声明（TS2591）。
- **`strict` + `noUncheckedIndexedAccess`**：数组下标取值的类型会带上 `undefined`，所以后面代码里写的是 `res.choices[0]?.message`——模型真的可能返回空 `choices`，编译器逼你处理它。
- **`verbatimModuleSyntax`**：只当类型用的导入必须写 `import type`（如 `import type OpenAI from "openai"`），运行时不会多加载东西。

> 不要用 `tsc --init --strict` 生成的模板：它不带 `"types": ["node"]`，模块设置也和上面不同。直接用这一份。

## 2.5 第一个程序：非流式调用

```ts
// 01-basic.ts —— 第一个 AI 程序
import "dotenv/config";
import OpenAI from "openai";

// 三件套实例化：换厂商只改 .env，代码零改动
const client = new OpenAI({
  apiKey: process.env.API_KEY,
  baseURL: process.env.BASE_URL,
});

// "type": "module" 下可以直接顶层 await，不用再包一层 main()
const res = await client.chat.completions.create({
  model: process.env.MODEL ?? "deepseek-flash",
  messages: [
    { role: "system", content: "你是一个简洁的技术助手。" },
    { role: "user", content: "用一句话解释什么是 token。" },
  ],
  temperature: 0.2, // 事实型问题用低温度（第 1 章原则）；换到 GPT-6 / Claude 新 API 时删掉这一行
  max_tokens: 200,  // 成本保险丝，永远设置（第 1 章原则）
});

console.log(res.choices[0]?.message.content);

// usage：你的成本仪表盘（第 1 章说的"计费单位"在这里落地）
console.log(`\n[用量] 输入 ${res.usage?.prompt_tokens} + 输出 ${res.usage?.completion_tokens} tokens`);
```

> **参数名小注**（2026-11 复核）：`max_tokens` 在 openai SDK 类型里已标记 deprecated，直连 OpenAI 新模型要改用 `max_completion_tokens`。GPT-6 系还有两处差异：推理强度不是 `none` 时必须去掉 `temperature`/`top_p`（否则报错），且 GPT-6 Astra / 6.1 Sol / 6.1 Terra 的**工具调用只在 Responses API 上可用**。o4-mini 已于 2026-10-23 关停；o3、gpt-5、gpt-5-mini、gpt-5-nano 于 2026-12-11 关停，gpt-5.1 于 2027-04-01 关停——新代码直连 OpenAI 时请以 GPT-6 系（gpt-6.1-sol / gpt-6.1-terra / gpt-6-luna）为默认。本课程主线的 DeepSeek / GLM / Kimi 兼容端点仍以 `max_tokens`、`temperature` 为标准参数、行为不变。

跑通它，然后做两个实验（必做，建立手感）：

- **实验 A**：把 `temperature` 改成 1.6 连跑三次，观察输出差异（第 1 章的采样理论肉眼可见）
- **实验 B**：换 `.env` 的三件套切到另一家（如 GLM 免费模型），确认**代码零改动**还能跑——这是兼容格式的威力

## 2.6 流式输出版本

第 1 章讲过：模型逐 token 生成，流式就是把「等全部生成完」变成「生成一个推一个」：

```ts
// 02-stream.ts —— 流式调用
import "dotenv/config";
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.API_KEY,
  baseURL: process.env.BASE_URL,
});

console.time("首token"); // 流式的价值指标：首 token 延迟，不是总时长

const stream = await client.chat.completions.create({
  model: process.env.MODEL ?? "deepseek-flash",
  messages: [{ role: "user", content: "写一首关于调试代码的五言绝句" }],
  stream: true,
  stream_options: { include_usage: true }, // 流式也要拿用量（多数兼容端支持，具体以各家文档为准）
  max_tokens: 200,
});

let first = true;
let text = "";
for await (const chunk of stream) {
  const delta = chunk.choices[0]?.delta?.content ?? "";
  if (delta && first) { console.timeEnd("首token"); first = false; }
  text += delta;
  process.stdout.write(delta);   // 不换行地逐段输出 → 终端里的打字机效果
  // 开了 include_usage 时，最后一个 chunk 的 choices 为空、带着 usage
  if (chunk.usage) console.log(`\n[用量] 输入 ${chunk.usage.prompt_tokens} + 输出 ${chunk.usage.completion_tokens} tokens`);
}

console.log(`[完整输出] ${text.length} 字符`);
```

注意你在这里扮演的是第 5 章里「服务端」的角色：**消费上游模型的流，转发给你的用户**。终端打字机效果和浏览器打字机效果，是同一条 token 流的两个出口。

## 2.7 统一封装 `lib/ai.ts`（全课程复用）

把本章所学固化成一个封装——**后面所有章节 import 它**，避免每章重复样板，也把「重试、取消、用量统计」的健壮性提前埋进地基：

```ts
// lib/ai.ts —— 课程统一 LLM 调用封装（第 02 章）
import "dotenv/config";
import OpenAI from "openai";

export const MODEL = process.env.MODEL ?? "deepseek-flash";

// 懒加载客户端：只有真正发请求时才读取 API_KEY。
// 好处：离线测试 import 本文件时不会因为没配 key 而在模块加载阶段就报错。
let _client: OpenAI | undefined;
export function getClient(): OpenAI {
  if (!_client) {
    if (!process.env.API_KEY) throw new Error("缺少 API_KEY：复制 .env.example 为 .env 并填写");
    _client = new OpenAI({
      apiKey: process.env.API_KEY,
      baseURL: process.env.BASE_URL,
      // 重试由下面的 chat() 自己做。SDK 默认还会自动重试 2 次，
      // 两层叠加会让一次失败变成 3×3=9 次请求——要么关掉 SDK 的，要么别手写。
      maxRetries: 0,
    });
  }
  return _client;
}

export interface ChatOptions {
  messages: OpenAI.Chat.Completions.ChatCompletionMessageParam[];
  model?: string;        // 覆盖默认 MODEL（第 17 章降级链/模型路由用）
  temperature?: number;  // 只在传了时才发送：GPT-6 推理模型与 Anthropic 新版 API 会拒绝该参数
  maxTokens?: number;
  json?: boolean;        // 第 04 章第一层保障：打开 JSON mode（response_format: json_object）
  retries?: number;      // 429/5xx 自动重试次数（默认 3）
  signal?: AbortSignal;  // 取消：用户点「停止」时一路传到这里，避免继续花钱
}

export interface ChatResult {
  text: string;
  finishReason: string;  // stop / length / tool_calls …（第 04 章：排查 JSON 截断的第一现场）
  usage: { input: number; output: number };
  durationMs: number;
}

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

/** 是否值得重试：限流与服务端错误重试；4xx 参数/鉴权错误重试也没用。 */
export function isRetryable(err: unknown): boolean {
  const status = (err as { status?: number } | null)?.status;
  return status === 429 || (status !== undefined && status >= 500);
}

export async function chat(opts: ChatOptions): Promise<ChatResult> {
  const retries = opts.retries ?? 3;
  const start = Date.now();

  for (let attempt = 0; ; attempt++) {
    try {
      const res = await getClient().chat.completions.create(
        {
          model: opts.model ?? MODEL,
          messages: opts.messages,
          ...(opts.temperature !== undefined ? { temperature: opts.temperature } : {}),
          ...(opts.json ? { response_format: { type: "json_object" as const } } : {}),
          // DeepSeek 等兼容端点用 max_tokens；OpenAI 官方已标注弃用，改用 max_completion_tokens
          max_tokens: opts.maxTokens ?? 1024,
        },
        { signal: opts.signal },
      );
      const choice = res.choices[0];
      return {
        text: choice?.message.content ?? "",
        finishReason: choice?.finish_reason ?? "unknown",
        usage: {
          input: res.usage?.prompt_tokens ?? 0,
          output: res.usage?.completion_tokens ?? 0,
        },
        durationMs: Date.now() - start,
      };
    } catch (err) {
      if (!isRetryable(err) || attempt >= retries) throw err;
      const backoff = 2 ** attempt * 500 + Math.random() * 300; // 指数退避 + 抖动
      console.warn(`[ai] 重试 ${attempt + 1}/${retries}，${Math.round(backoff)}ms 后`);
      await sleep(backoff);
    }
  }
}
```

设计意图（面试可讲）：

- **错误分类重试**：429（限流）和 5xx（服务端错误）可重试；400（参数错）401（Key 错）重试也没用，直接抛——**盲目重试不可重试的错误**是新手最常见的浪费。`isRetryable` 只读错误对象上的 `status` 字段，不写 `err as OpenAI.APIError`：在 openai 7.x 里 `OpenAI.APIError` 是一个类（值），不能当类型用，那样写直接编译失败；按字段判断还顺带兼容其他 SDK 抛出的错误。网络断开、连接超时这类错误没有 `status`，这里不重试（练习 5 让你扩展它）。
- **只有一层重试**：openai SDK 默认自己会重试 2 次。如果不设 `maxRetries: 0`，SDK 的重试和 `chat()` 的重试会**相乘**：默认 `retries: 3` 时，一次 `chat()` 最坏会发出 (3+1)×(2+1) = 12 次请求，而你以为只有 4 次。两层重试只能留一层，本课程留自己写的这层（能打日志、能控制退避）。
- **懒加载客户端**：`getClient()` 第一次真正发请求时才检查 `API_KEY`。离线测试 import 这个文件时不需要 key——这就是 `code/` 里 `pnpm check` 不需要 key 的原因之一。
- **`temperature` 只在传了时才发**：换到会拒绝该参数的模型（GPT-6 推理模型、Anthropic 新版 API）时，调用方不传即可，封装不用改。
- **`json` 与 `signal`**：`json: true` 打开 JSON mode，是第 4 章结构化输出的第一层保障；`signal` 一路传到 SDK，第 5 章用户点「停止」时就靠它让请求真正中止、不再继续计费。
- **指数退避 + 随机抖动**：等的时间翻倍增长，加随机量防止并发客户端同步重试造成二次冲击。
- **`finishReason`、usage 与耗时永远带回**：`finishReason` 是第 4 章排查 JSON 截断的第一现场；每次调用都有成本与延迟数据——第 16 章可观测性的种子在这里埋下。

## ⚠️ 常见坑

1. **PowerShell 执行策略**报「禁止运行脚本」→ `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。
2. **`ERR_PNPM_IGNORED_BUILDS`**：pnpm 12 拦下了依赖的构建脚本（第一个通常是 tsx 依赖的 esbuild）→ `pnpm approve-builds esbuild`，并把生成的 `pnpm-workspace.yaml` 提交进 Git。
3. **Key 写进代码推到 GitHub** → 机器人几分钟内扫到并盗刷。`.env` 进 `.gitignore`，泄露立即重置。检查工具：`git status` 里永远不该看到 `.env`。
4. **国内访问国际厂商超时** → 用国内厂商（DeepSeek/GLM/Kimi 全部可用），或 OpenRouter；`fetch failed` 多数是网络问题不是代码问题。
5. **模型名写死且过期**（如 `deepseek-chat`：官方 2026-04-24 预告三个月后停用，现在价格页已不再列出它，现役为 `deepseek-flash` / `deepseek-v4-pro`；Kimi 的 K2 系列 2026 年底下线）→ 三件套 + 起手 `console.log(MODEL)` 排查；现役模型名见附录 B。
6. **流式在 PowerShell 里乱码/卡顿** → 用 `process.stdout.write` 而非逐 token `console.log`（后者每 token 一个换行）；Windows 老终端对 UTF-8 支持差可用 Windows Terminal。
7. **401 但 Key 明明对** → 检查 BASE_URL 与 Key 是否同一家（拿 DeepSeek 的 Key 去请求 OpenAI 的 URL 是高频乌龙）；检查 `.env` 是否被 `dotenv/config` 加载（变量名拼写）。`lib/ai.ts` 报「缺少 API_KEY」也是这个原因。
8. **类型检查报 `process` 未声明 / 相对导入要求写 `.js`** → tsconfig 不是 2.4 那一份（缺 `"types": ["node"]`，或用了 `NodeNext`）。
9. **`Top-level await is currently not supported with the "cjs" output format`** → `package.json` 缺 `"type": "module"`。
10. **换到 GPT-6 / Claude 后 400** → 先看 2.1「换厂商的边界」：多半是带了 `temperature`、用了 `json_object` 或在 Chat Completions 上调工具。
