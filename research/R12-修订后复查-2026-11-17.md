## 3. 分文件问题（按严重度）

### P0-1 · 第 14 章 L97（以及 L6、L91 的叙述）：`embed` 已不存在

- **证据**：`code/src/lib/embed.ts` 的导出只有 `Embedder`、`OpenAIEmbedderOptions`、`openAIEmbedder`、`cosineSim`、`fakeEmbedder`（`grep '^export'`）。第 12 章 L41-80 节选的就是这个文件。tsc：`memory/store.ts(5,10): error TS2305: Module '"../lib/embed"' has no exported member 'embed'.` L148 `await embed(...)` 与 L167 `await embed([query])` 随之失效。
- **影响**：第 14 章的核心产出（长期记忆系统）照抄编译不过。
- **修复**：L97 改为
  ```ts
  import { openAIEmbedder, type Embedder } from "../lib/embed";   // 第 12 章：工厂函数，测试时可换 fakeEmbedder()
  ```

  在 `MemoryStore` 的构造参数里加 `embed: Embedder = openAIEmbedder()`，L148/L167 改成 `this.embed(...)`。L6、L91 的「`embed()`」改为「`openAIEmbedder()` 返回的 embed 函数」。

### P0-2 · 第 19 章 L109-131、L154-178：PG 版存储与新的第 05 章脱节

- **证据**：第 05 章 `lib/store.ts`（L454-524）现在导出 `ChatUIMessage`、`saveUserMessage`、`saveAssistantMessage`、`loadModelHistory`、`loadUIMessages`、`listConversations`，表结构有 `conversations` 表以及 `messages.ui_id UNIQUE`、`messages.status`。第 19 章 L154 写「函数签名不变，路由代码一行不用改」，但它的 `lib/store.ts` 只有 `saveMessages`/`loadHistory`，`db/schema.ts` 也没有 `conversations`、`ui_id`、`status`。把它替换进项目 1 后，tsc 报 9 个错误（见 2.2 的 `next19`）。另外，第 05 章的函数是同步的（better-sqlite3），PG 版必然是异步的，路由里的调用都要加 `await`。
- **修复**：
  1. `db/schema.ts` 增加 `conversations`（id/title/createdAt）表，并给 `messages` 加 `uiId: text("ui_id").unique()` 和 `status: text("status", { enum: ["done","cancelled","timeout"] }).notNull().default("done")`。
  2. `lib/store.ts` 按第 05 章的 6 个导出逐一给出 async 实现，重新导出 `ChatUIMessage` 类型。
  3. 把 L154 改为：「函数名与参数不变，但都变成 async：第 05 章 route.ts / page 数据加载处的调用前加 `await`（共 N 处）」，并给出 route.ts 的改动 diff。

### P1-3 · 第 20 章 L99（并波及第 05 章 L254/L309、第 18 章）：AI SDK 7.0.171 起工具错误原文会发到前端

- **证据**：`ai` 7.0.171（registry 时间 2026-11-12T20:22Z，早于时效报告，报告未收录）的 CHANGELOG 写道：`toUIMessageStream` 以前默认把失败工具调用的错误替换成 "An error occurred."；现在 "UI messages now keep the model's error text for tool execution errors and invalid tool calls. This text reaches the client"，可以用新选项 `redactToolErrors: true` 恢复旧行为；"A provided `onError` keeps handling failed tool calls unless you set `redactToolErrors: false`"；"Stream errors are still masked by default"（<https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md>）。本地 `ai@7.0.173` 的 `index.d.ts` L2801、L7289 有 `redactToolErrors?: boolean`。
