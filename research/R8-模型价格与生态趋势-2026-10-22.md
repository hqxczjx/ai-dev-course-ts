## 三、生态与协议动态

### 3.1 MCP：仍是事实标准，但规范已“无状态化”

**当前规范版本：`2026-07-28`**（官方规范站，2026-10-22 读取）。

关键变化：

1. **无状态、自包含请求**：不再依赖 `initialize` 握手建立会话；每个请求自带协议版本、客户端身份与能力。
2. **每请求版本协商**：版本放在 `_meta.io.modelcontextprotocol/*`；HTTP 还镜像到 `MCP-Protocol-Version` 头。服务端不支持该版本时必须返回 `UnsupportedProtocolVersionError`，并列出支持的版本。
3. **`server/discover`**：服务端 **MUST** 实现；客户端可在首个请求前调用，了解服务端支持的版本与能力。
4. **兼容旧版**：`2025-11-25` 及更早是 legacy（`initialize` 握手）；同时支持现代与 legacy 的实现叫 dual-era。
5. **传输不变**：stdio（换行分隔 JSON-RPC）与 Streamable HTTP（单端点 POST，JSON 或请求级 SSE 流）；另可自定义传输。
6. **扩展**：Tasks（长任务异步执行、轮询、mid-flight input、durable handle）、Skills over MCP（结构化 Agent 指令）、MCP Apps（对话内嵌 UI）。

**判断**：

- MCP 仍是 Agent↔工具/数据层的事实标准：官方规范持续更新，TS SDK v2（`@modelcontextprotocol/server` / `client` 2.3.1）已封装新规范，AAIF 的创始项目之一就是 MCP。
- 教程第 09 章的代码无需改动；但“面试新热点”可以升级为“无状态 + 每请求版本协商 + `server/discover` + Tasks/Skills/MCP Apps 扩展”。
- “MCP 是岗位硬要求”是**求职市场判断**，不是协议事实；2026 H2 没有找到可公开复核的官方岗位报告支持这个精确表述（见 3.6）。

**来源**：MCP Specification 2026-07-28 <https://modelcontextprotocol.io/specification/2026-07-28>；Versioning and Compatibility <https://modelcontextprotocol.io/specification/2026-07-28/basic/lifecycle>；Transports <https://modelcontextprotocol.io/specification/2026-07-28/basic/transports>；Extensions <https://modelcontextprotocol.io/extensions/overview>（均 2026-10-22）。

### 3.2 A2A：v1.0 + AAIF，已进入生产采用期

- **规范版本**：最新发布 **1.0.0**；v1.0.0 GitHub Release 2026-03-12，v1.0.1 补丁 2026-05-28。请求用 `A2A-Version: 1.0` 头做版本协商。
- **治理**：最初由 Google 发起，后捐赠给 Linux Foundation；2026-08-27 官方宣布以 **Growth Stage 项目**加入 **Agentic AI Foundation（AAIF）**，与 MCP、goose、AGENTS.md 等成为 sibling projects。
- **生态规模**：官方称 **150+ 组织**支持；Google Cloud、AWS Bedrock AgentCore、Azure AI Foundry 原生支持；ServiceNow、Salesforce、Atlassian、SAP 等企业软件在用；LangGraph、CrewAI、Pydantic AI、AG2、IBM BeeAI 等框架支持。
- **绑定**：JSON-RPC 2.0、gRPC、HTTP+JSON/REST 三种；核心数据模型以 `spec/a2a.proto` 为权威定义。
- **核心概念**：Agent Card（能力/联系方式/认证方式）、任务委派、流式事件、推送通知、扩展与自定义绑定。
- **新增工具**：A2A CLI 于 2026-10-01 发布，可在终端发现、发消息、管理任意 A2A Agent。

**判断**：A2A 不再是“早期概念”，已进入生产采用期；但岗位要求仍远少于 MCP。教程第 11 章应把“A2A 处于早期但值得跟踪”改为“已进入生产采用期，但岗位要求仍远少于 MCP”。

**来源**：A2A Specification <https://a2a-protocol.org/latest/specification/>；A2A v1.0.0 Release <https://github.com/a2aproject/A2A/releases/tag/v1.0.0>；A2A 加入 AAIF <https://a2a-protocol.org/latest/blog/2026/08/27/a-new-chapter-for-a2a-joining-the-agentic-ai-foundation/>；AAIF 新闻稿（247 家成员，2026-08-13）<https://www.linuxfoundation.org/press/agentic-ai-foundation-welcomes-57-new-members-gaining-major-financial-services-players-and-apac-leaders>（均 2026-10-22）。

### 3.3 AG-UI 与其他 Agent-UI 协议

- **AG-UI 当前规范：1.0**（`https://ag-ui.com/spec/1.0`）。仓库最新滚动发布 `release/2026-10-21`（2026-10-21），说明协议仍在活跃迭代。
- **定位**：Agent↔用户/前端的事件协议；官方明确把它与 MCP（Agent↔工具/数据）、A2A（Agent↔Agent）并列为“AI 协议栈的第三条腿”。
- **传输**：HTTP + SSE、HTTP + Protobuf，以及自定义绑定契约。
- **事件族**：Run/Step 生命周期、Text Messages、Tool Calls、Reasoning、State、Activity、Subagents、Raw/Custom。
- **与生成式 UI 的关系**：AG-UI 负责“Agent 事件流 ↔ 前端”；MCP-UI、Open JSON UI、A2UI 是“Agent 下发 UI 组件”的生成式 UI 规范，二者互补，不是替代关系。
- **生态**：官方集成表列出 AWS Bedrock AgentCore、Claude Agent SDK、Claude Managed Agents、LangGraph、CrewAI、Cloudflare Agents、Mastra 等；A2A Middleware、MCP Apps 也在列。

**其他 Agent-UI 协议**：

- **A2UI**：生成式 UI 规范，让 Agent 返回 UI widget/组件描述；不是 Agent↔前端的全量事件协议。
- **MCP Apps**：MCP 扩展，把交互式 UI（图表、表单、视频）内嵌到对话中；与 AG-UI 可同时使用。
- **Open JSON UI**：另一套生成式 UI 描述规范；AG-UI 官方称可与它协作。

**判断**：教程第 20 章目前讲“事件流 UI”但没有点名 AG-UI，建议至少加一段“协议层”说明（见 P2-2）。不需要把整章改写为 AG-UI 教程，现有 Vercel AI SDK `message.parts` + 工具状态机仍是很好的工程主线。

**来源**：AG-UI Spec 1.0 <https://ag-ui.com/spec/1.0>；AG-UI “MCP, A2A, and AG-UI” <https://ag-ui.com/agentic-protocols>；AG-UI Releases <https://github.com/ag-ui-protocol/ag-ui/releases>；AG-UI 首页集成表 <https://ag-ui.com/>（均 2026-10-22）。

  - 美国软件开发者岗位自 Claude Code 发布（2025-02 底）以来增长近 **15%**，同期整体岗位下降 **7%**；
