## 第 6 章 · AI 编程工具方法论

### 1. CLAUDE.md 精简建议、Bloated 警告、`/init` 与 `/doctor`

- 教程原文（6.4）：「堆 500 行规则的代价是每次对话都变贵变慢……目标：一屏以内，超过就删旧」；「给 Claude Code 用 `/init` 可自动生成初版 CLAUDE.md」→ **✅ 方向属实，且官方依据更硬**
  - 官方 memory 文档：「target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence.」（还有硬上限：单文件 >4 MiB 直接跳过；MEMORY.md 索引只加载前 200 行/25KB）
  - 官方 best-practices 文档原话警告：「**Bloated CLAUDE.md files cause Claude to ignore your actual instructions!**」「If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long.」——教程"遵循率下降"的说法与官方一致
  - `/init` 存在（官方：「Run `/init` to generate a starting CLAUDE.md automatically」，已存在时不覆盖而是提改进建议）；`/doctor` 也存在（v2.1.206+ 提供 CLAUDE.md 瘦身建议，v2.1.283+ 有 `/doctor prompt-audit`）——教程未提 `/doctor`，不算错误
  - 建议：教程可把"一屏以内"补上官方数字锚点「<200 行」并引用 Bloated 警告，说服力更强
  - 来源：https://code.claude.com/docs/en/memory ｜ https://code.claude.com/docs/en/best-practices

### 2. SKILL.md frontmatter、<500 行、渐进式披露

- 教程原文（6.7）：frontmatter 只给 `name` + `description`；「description 是触发器……只看描述就能决定不加载，省上下文。这是渐进式披露的第一层」「更长的参考资料放同目录附属文件……这是渐进式披露的第二层」→ **✅ 内容无错 / ⚠️ 层数不全**
  - claude.ai 侧确实仅允许 6 个标准字段：`name, description, license, compatibility, metadata, allowed-tools`（多写会报 "Unexpected key(s) in SKILL.md frontmatter"；Claude Code 侧全字段可接受）。注意：**Claude Code 文档说所有字段皆可选、仅 description 为推荐项**，教程模板带 name+description 的写法安全无误
  - <500 行建议属实：「Keep `SKILL.md` under 500 lines. Move detailed reference material to separate files.」
  - 渐进式披露官方为**三层**：① description 常驻上下文 → ② SKILL.md 正文在调用时加载 → ③ 附属文件（reference.md 等）按需读取。教程把 ①② 合并成"第一层"、③ 当"第二层"，自测题也问"两层含义"——内部自洽但与官方三层表述不一致，建议改为三层（或注明"官方拆为三层，本章归并为两层讲"）
  - 来源：https://code.claude.com/docs/en/skills

### 3. Cursor Rules

  - 来源：https://cursor.com/docs/context/rules
