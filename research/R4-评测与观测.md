## 1. promptfoo —— prompt/模型对比评测 + 红队测试（CLI 工具）

### 1.1 现状与安装

- 定位：开源的 CLI + 库，用于评测与红队测试 LLM 应用（"promptfoo is a CLI and library for evaluating and red-teaming LLM-based apps"）。来源：https://github.com/promptfoo/promptfoo
- npm 包名：**`promptfoo`**。当前最新 **0.124.1**（2026-10-08 发布，更新极活跃），描述 "LLM eval & testing toolkit"。来源：https://registry.npmjs.org/promptfoo
- GitHub 约 25.9k stars（2026-10 查看）。来源：https://www.promptfoo.dev/docs/getting-started/
- 安装：`npm install -g promptfoo` 或免安装 `npx promptfoo@latest`。来源：https://www.promptfoo.dev/docs/getting-started/

### 1.2 核心功能（官方文档核实）

- **prompt/模型对比**：同一组 prompt 跑多个 provider（官方称 60+ providers：OpenAI、Anthropic、Google、Ollama、自定义 JS/Python 等），`promptfoo view` 打开本地 Web UI 对比输出；CLI 可临时换模型：`promptfoo eval -r google:gemini-3.8-flash`。来源：https://www.promptfoo.dev/docs/getting-started/
- **断言（asserts）**：分两类（来源：https://www.promptfoo.dev/docs/configuration/expected-outputs/）：
  - 确定性：`equals`、`contains`/`icontains`、`regex`、`is-json`、`is-sql`、`javascript`（自定义 JS 校验）、`webhook`、`levenshtein`、`rouge-l/n/s`、`bleu`、`latency`、`cost`、`is-refusal`、`is-valid-function-call` 等；
  - 模型辅助（LLM-as-judge）：`similar`（embedding 余弦）、`classifier`、`moderation`、`llm-rubric`、`g-eval`、`factuality`、`answer-relevance`、`context-faithfulness/recall/relevance`、`select-best` 等。
  - 任意断言可用 `not-` 前缀取反。
- **LLM-as-judge（llm-rubric）最小示例**（官方文档摘录，来源：https://www.promptfoo.dev/docs/configuration/expected-outputs/）：
  ```yaml
  assert:
  - type: llm-rubric
    value: Is spoken like a pirate
    metric: Tone
  ```
  字符串简写：`llm-rubric:Is helpful and accurate`；可指定 judge `provider` 与自定义 `rubricPrompt`。
- **红队（red teaming）**：独立产品线，用于 LLM 应用安全测试与漏洞扫描（官网导航即含 Red teaming；第三方对比称其有 40+ 攻击插件，覆盖越狱、注入等）。来源：https://www.promptfoo.dev 、https://github.com/promptfoo/promptfoo
- **CI 集成**：官方 GitHub Action `promptfoo/promptfoo-action`（PR 上自动评评测并评论通过/失败计数，支持缓存与 flaky 重跑）。示例（官方 README 摘录，来源：https://github.com/promptfoo/promptfoo-action ）：
  ```yaml
  on:
    pull_request:
      paths:
        - 'prompts/**'
        - 'promptfooconfig.yaml'
  # ...
      - name: Run promptfoo evaluation
        uses: promptfoo/promptfoo-action@v1
        with:
          openai-api-key: ${{ secrets.OPENAI_API_KEY }}
  ```

### 1.3 配置文件格式与 TS 支持

- 默认配置文件 **`promptfooconfig.yaml`**（也支持 JSON）。
- 官方配置指南原文："Test files can be defined in YAML/JSON, JSONL, CSV, and TypeScript/JavaScript."——即**测试用例文件明确支持 TS/JS**。来源：https://www.promptfoo.dev/docs/configuration/guide
- 主配置文件本身也支持写成 `promptfooconfig.ts`（default export，类型为 `UnifiedConfig`）：官方仓库 2025-01 有 issue "Unable to run Promptfoo configs written in Typescript since update to version 0.103.17"，证明该能力存在（该版本曾回归后修复）；但**官方配置指南只把 YAML/JSON 作为主配置的一等格式**，TS 配置属可用但文档化较弱的用法。教程建议：主配置用 YAML、测试用例用 TS。来源：https://github.com/promptfoo/promptfoo/issues （搜 "Typescript configs 0.103.17"）

### 1.4 最小配置示例（官方 Getting Started 摘录）

来源：https://www.promptfoo.dev/docs/getting-started/ （模型名为文档当日原文）：

```yaml
prompts:
- 'Convert the following English text to {{language}}: {{input}}'
providers:
- openai:gpt-6-sol
- openai:gpt-6-luna
tests:
- vars:
    language: French
    input: Hello world
  assert:
  - type: contains
    value: 'Bonjour le monde'
```

运行：`export OPENAI_API_KEY=...` → `promptfoo eval` → `promptfoo view`。脚手架：`promptfoo init --example getting-started`。

## 2. autoevals —— 代码内评测打分库（Braintrust 出品）

- 是什么：把常用自动评测方法打包成库的三方中立 npm 包，由 **Braintrust 团队维护**，含 LLM-as-judge、启发式（Levenshtein 等）与统计指标（BLEU 等）；多数 model-graded 评测改编自 OpenAI 的 evals 项目，但支持单条运行、可调 prompt、可调试输出。来源：https://github.com/braintrustdata/autoevals
- npm：**`autoevals`**，最新 **0.4.0**（2026-10-07 更新），描述 "Universal library for evaluating AI models"。来源：https://registry.npmjs.org/autoevals
- 内置指标（README 核实）：
  - **LLM-as-judge**：Battle、Closed QA、Humor、**Factuality**、Moderation、Security、Summarization、SQL、Translation、微调二分类器；
  - **RAG**：context precision / **context relevancy** / context recall、context entity recall、faithfulness、answer relevancy、answer similarity、answer correctness；
  - **复合/结构**：semantic list contains、JSON validity；
  - **Embedding**：embedding similarity；
  - **启发式**：Levenshtein、exact match、numeric difference、JSON diff。
- 依赖：默认用 `OPENAI_API_KEY`，可通过 `OPENAI_BASE_URL` / Braintrust Gateway / 自定义 OpenAI 兼容客户端换模型。每个 scorer 返回 `Score` 对象（`name`、`score` 0–1 或 null、`metadata`）。
- **最小用法（官方 README 的 TypeScript 示例，逐字摘录）**：

  ```typescript
  import { Factuality } from "autoevals";

  (async () => {
    const input = "Which country has the highest population?";
    const output = "People's Republic of China";
    const expected = "China";

    const result = await Factuality({ output, expected, input });
    console.log(`Factuality score: ${result.score}`);
  })();
  ```

  来源：https://github.com/braintrustdata/autoevals
- 与框架无关（不绑 Braintrust 平台），适合做"代码内断言/自定义 judge"的教学件。

## 3. Langfuse —— 全链路追踪 + 数据集评测（可自部署）

### 3.1 TS SDK 包名（重要：2026 年已模块化为 v5）

- JS/TS SDK 现为 **v5**（v4 于 2025-08-28 GA，基于 OpenTelemetry 重写；官方建议 v3 用户直接升 v5）。来源：https://langfuse.com/changelog/2025-08-28-typescript-sdk-v4-ga 、https://langfuse.com/docs/observability/sdk/upgrade-path/js-v3-to-v4
- 当前包（官方 SDK 总览，来源：https://langfuse.com/docs/observability/sdk/overview ）：
  - `@langfuse/tracing` —— 追踪 API（`startObservation` / `startActiveObservation` / `observe`）
  - `@langfuse/otel` —— `LangfuseSpanProcessor`（导出 span 到 Langfuse，需 **Node ≥ 20**）；npm 最新 5.13.1（2026-10-07，registry 核实）
  - `@langfuse/client` —— 非追踪功能（prompt 管理、数据集、打分），入口 `LangfuseClient`
  - `@langfuse/openai` —— OpenAI SDK 自动追踪（`observeOpenAI`）
  - `@langfuse/langchain`、`@langfuse/browser`、`@langfuse/core`
  - `@langfuse/vercel-ai-sdk` —— Vercel AI SDK 7 集成（需 Node 22+，npm 5.13.1，2026-10-07，registry 核实）
- **`@langfuse/nodejs` 是 v3 时代的旧包名**：v3 的 `langfuse.trace()/.span()/.generation()` 在 v4+ 被 `@langfuse/tracing` 的 `startObservation`、`startActiveObservation` 取代，官方迁移指南称 "The SDK is now built on top of OpenTelemetry"。教程应直接教新包。来源：https://langfuse.com/docs/observability/sdk/upgrade-path/js-v3-to-v4
- **官方最小示例（SDK 总览逐字摘录）**，来源：https://langfuse.com/docs/observability/sdk/overview ：

  ```ts
  // instrumentation.ts
  import { NodeSDK } from "@opentelemetry/sdk-node";
  import { LangfuseSpanProcessor } from "@langfuse/otel";

  export const sdk = new NodeSDK({
    spanProcessors: [new LangfuseSpanProcessor()],
  });

  sdk.start();
  ```

  ```ts
  // index.ts
  import { sdk } from "./instrumentation";
  import { startActiveObservation } from "@langfuse/tracing";

  async function main() {
    await startActiveObservation("my-first-trace", async (span) => {
      span.update({
        input: "Hello, Langfuse!",
        output: "This is my first trace!",
      });
    });
  }

  main().finally(() => sdk.shutdown());
  ```

  凭据走环境变量 `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_BASE_URL`；短生命周期进程必须 `sdk.shutdown()` 冲刷。

### 3.2 与 OpenAI SDK 的包装集成

- 包：`@langfuse/openai`（兼容 **openai >= 4.0.0**，支持 Chat Completions 与 Responses API，不支持 Assistants API）。官方示例（逐字摘录，来源：https://langfuse.com/integrations/model-providers/openai-js ）：
  ```ts
  const openai = observeOpenAI(new OpenAI());

  const res = await openai.chat.completions.create({
    messages: [{ role: "system", content: "Tell me a story about a dog." }],
  });
  ```
  包装后按原样使用，自动记录延迟、流式首 token、错误、token 用量/成本；第二参 `langfuseConfig` 可加 `generationName`/`sessionId`/`userId`/`tags`。

### 3.3 与 Vercel AI SDK 的集成

来源：https://langfuse.com/docs/integrations/vercel-ai-sdk
- **AI SDK 7（当前主线）**：装 `@langfuse/vercel-ai-sdk`（Node 22+），启动时注册一次 `registerTelemetry()`；AI SDK 调用**默认**发遥测，无需逐调用开关。
- **AI SDK v6（旧）**：需逐调用 `experimental_telemetry: { isEnabled: true }`，并注册 `LangfuseSpanProcessor`：
  ```ts
  import { NodeSDK } from "@opentelemetry/sdk-node";
  import { LangfuseSpanProcessor } from "@langfuse/otel";

  const sdk = new NodeSDK({
    spanProcessors: [new LangfuseSpanProcessor()],
  });

  sdk.start();
  ```
- 进阶：`langfusePrompt: prompt.toJSON()` 可把 Generation 关联到 Langfuse 的 prompt 管理；serverless/Next.js 结束前要 `forceFlush()`；`@langfuse/tracing` 的 `observe()` / `propagateAttributes()` 可补 trace 名、userId、sessionId、tags；排查用 `LANGFUSE_LOG_LEVEL="DEBUG"`。
- 注意：连接方式是 **span processor 进程内拦截**（AI SDK 与 Langfuse 都讲 OpenTelemetry），不是把 span 推到一个独立 OTel collector 端点。

### 3.4 Evals 功能（数据集 / 实验 / 评分）

来源：https://langfuse.com/docs/evaluation/core-concepts 、https://langfuse.com/docs/evaluation/experiments/data-model
- **Dataset**："A collection of test cases (dataset items)"，每条含 input（可选 expected output）；**Experiment run** = "A single execution of your task against all items in a dataset, producing outputs (and scores)"，多次 run 可对比决定是否上线。
- **离线/在线评测闭环**：离线对固定数据集迭代 prompt/模型；线上用规则（过滤 + 采样率）触发 evaluator 对生产 trace 打分，bad case 回填数据集。
- **Score**：统一结果对象（`NUMERIC`/`CATEGORICAL`/`BOOLEAN`/`TEXT`），来源四类：用户/人工反馈（UI、标注队列）、LLM-as-judge、决策模型 evaluator、**代码 evaluator（支持自定义 TypeScript 逻辑）**。
- 实验可用 SDK（TS）跑（task + evaluator 全在代码里），或 UI / OTel 属性方式。

### 3.5 核心概念（官方 Glossary 逐字摘录）

来源：https://langfuse.com/docs/glossary
- **Trace**："A single request or operation in your LLM application."（含总 input/output/metadata 与嵌套 observations）
- **Span**："An observation type that represents the duration of a unit of work in a trace."
- **Generation**："An observation type that logs outputs from AI models including prompts, completions, token usage, and costs."
- **Event**：离散事件；**Observation**：trace 内一步（span/generation/event/tool 等，可嵌套）；**Session**：把多轮会话的 traces 分组。

### 3.6 自部署（docker-compose）

来源：https://langfuse.com/self-hosting 、https://langfuse.com/self-hosting/deployment/docker-compose
- Langfuse 开源（FAQ 原话 "Langfuse is open source and you can self-host it for free"），本地/单机用 Docker Compose，生产可用 Kubernetes Helm / AWS / Azure / GCP。
- v4+ 架构只依赖开源组件：**PostgreSQL**（事务数据）、**ClickHouse**（traces/observations/scores）、**Redis/Valkey**（缓存+队列）、**S3/Blob**（原始事件/附件）；两个应用容器：`langfuse/langfuse`（Web/UI/API）+ `langfuse/worker`（异步处理）。
- 快速启动（官方文档摘录）：
  ```bash
  git clone https://github.com/langfuse/langfuse.git
  cd langfuse
  # 修改 docker-compose.yml 中标记 # CHANGEME 的密钥
  docker compose up
  ```
  2–3 分钟后访问 `http://localhost:3000`；**无默认账号**，首次 Sign up 创建用户；VM 建议 4 核/16 GiB；升级 `docker compose up --pull always`。

## 4. Vercel AI SDK 的 Telemetry

来源：https://ai-sdk.dev/docs/ai-sdk-core/telemetry （2026-10 核实，对应 AI SDK 7 时代）
- 机制：AI SDK 用 **OpenTelemetry** 为文本/对象生成、embedding、rerank、语音、转写发 span。
- **新版默认开启**（原文 "Once a telemetry integration is registered, supported AI SDK calls emit telemetry events by default."）：注册集成后自动发遥测，逐调用 `telemetry: { isEnabled: false }` 退出；`telemetry` 选项现在主要用于 `functionId`/metadata。旧版（v5/v6 时代）的 `experimental_telemetry: { isEnabled: true }` 逐调用开关在 v6 legacy 路径仍存在。
- 新集成入口：**`@ai-sdk/otel` 包的 `OpenTelemetry`**，遵循 **GenAI 语义约定**（`gen_ai.*` 属性）：根 span 如 `invoke_agent {modelId}`，内嵌 `chat {modelId}`、`execute_tool {toolName}`；`LegacyOpenTelemetry` 发旧 `ai.*` span。
- Next.js 最小接入（官方文档逐字摘录）：
  ```ts
  import { registerOTel } from '@vercel/otel';
  import { registerTelemetry } from 'ai';
  import { OpenTelemetry } from '@ai-sdk/otel';

  export function register() {
    registerOTel({ serviceName: 'my-ai-app' });
    registerTelemetry(new OpenTelemetry());
  }
  ```
- `telemetry.functionId` 记为 `gen_ai.agent.name` / `resource.name`；输入输出默认记录（`recordInputs` / `recordOutputs` 可关）；还支持自定义 `Telemetry` 接口（`onStart`/`onEnd` 钩子）、Node tracing channel（`ai:telemetry`）、`enrichSpan`。
- **导出到 Langfuse**：两条路——(a) Langfuse 官方的 `@langfuse/vercel-ai-sdk`（AI SDK 7，`registerTelemetry()` 一次注册）；(b) 旧版用 `LangfuseSpanProcessor` 挂进 OTel NodeSDK（见 3.3）。Next.js 官方 `@vercel/otel` 的 `registerOTel` 要求 v2+（旧版不支持 OTel JS SDK v2）。

## 5. OpenTelemetry GenAI 语义约定

- 位置变更：GenAI 约定已从 opentelemetry.io 主 semconv 仓库**迁出**至专仓 **https://github.com/open-telemetry/semantic-conventions-genai**（原页面只剩迁移公告："GenAI semantic conventions have moved…"）。来源：https://opentelemetry.io/docs/specs/semconv/gen-ai/
- **成熟度：GenAI 专属属性仍为 Development 状态**；仅共享属性（`error.type`、`server.address`、`server.port`）为 Stable。教程措辞注意"发展中、可能变更"。来源：https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md
- 覆盖：GenAI client span/metric/event、agent span、MCP、异常，及 provider 专有约定（OpenAI、Anthropic、AWS Bedrock、Azure AI Inference）。
- 关键 span 名与属性（官方文档核实，来源同上）：
  - span 名模板：`{gen_ai.operation.name} {gen_ai.request.model}`（embeddings 等）；`execute_tool {gen_ai.tool.name}`
  - `gen_ai.operation.name`：`chat`、`embeddings`、`retrieval`、`fetch_response`、`execute_tool`、`generate_content`、`text_completion`、memory 操作等
  - `gen_ai.request.model` / `gen_ai.response.model`、`gen_ai.provider.name`（`openai`、`anthropic`、`aws.bedrock`、`gcp.vertex_ai`）
  - `gen_ai.usage.input_tokens`（应含缓存 token；有计费口径时上报计费数）、`gen_ai.response.finish_reasons`（如 `["stop","length"]`）
  - 内容类属性默认**不采集**（敏感），需 opt-in（如 `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`）：`gen_ai.system_instructions`、`gen_ai.input.messages`、`gen_ai.output.messages`
  - 工具：`gen_ai.tool.name`、`gen_ai.tool.call.arguments`、`gen_ai.tool.call.result`；检索：`gen_ai.retrieval.top_k`、`gen_ai.retrieval.documents` 等
- 对教程的意义：AI SDK 7 的 `@ai-sdk/otel` 与 Langfuse v5 都讲这套 `gen_ai.*` 约定，是两者互通的基础。

## 7. DeepEval 有 JS/TS 版吗？—— 2026 年有了（官方）

- 主体仍是 Python（pytest 风格："similar to Pytest but specialized for unit testing LLM apps"，`pip install -U deepeval`、`deepeval test run`，要求 Python ≥ 3.9）。来源：https://github.com/confident-ai/deepeval
- **但已有官方 npm 包 `deepeval`**（v0.9.22，2026-10 发布；维护者邮箱为 confident-ai.com，指向同一 GitHub 仓库），描述逐字："**The LLM Evaluation Framework for TypeScript**"。来源：https://registry.npmjs.org/deepeval
- 形态：**插进 Vitest 体系**——`npm install --save-dev deepeval`，`npx deepeval test run` 像 vitest 一样收集运行 eval 文件；`import "deepeval/vitest"` 注册 `toPass()` 匹配器；导出子模块 `./metrics`、`./dataset`、`./test-case`、`./vitest`，及集成（LangChain、Mastra、ai-sdk/Vercel AI SDK、openai-agents、openinference）。来源：https://deepeval.com/docs/getting-started
- 官方快速开始示例（逐字摘录，节选）：
  ```typescript
  import { it, expect } from "vitest";
  import { LLMTestCase, SingleTurnParams } from "deepeval/test-case";
  import { GEval } from "deepeval/metrics";
  import "deepeval/vitest";

  it("gives medically sound advice", async () => {
    const correctnessMetric = new GEval({
      name: "Correctness",
      criteria:
        "Determine if the 'actual output' is correct based on the 'expected output'.",
      evaluationParams: [
        SingleTurnParams.ACTUAL_OUTPUT,
        SingleTurnParams.EXPECTED_OUTPUT,
      ],
      threshold: 0.5,
    });
    // ...构造 testCase...
    await expect(testCase).toPass([correctnessMetric]);
  });
  ```
  来源：https://deepeval.com/docs/getting-started
- 结论：教程可提及"DeepEval 已官方支持 TS（Vitest 集成，较新）"，但作为主打需观察成熟度（0.x 版本）。

## 8. 其他：OpenAI Evals API 与 LangSmith 的 TS 支持

### 8.1 OpenAI Evals API（官方 TS SDK 原生支持）

- openai-node 的 `src/resources/evals/`（evals.ts、runs/）与 `graders.ts` 均存在——即 **`client.evals` / `client.evals.runs` / `client.graders` 已进入官方 openai npm SDK**。来源：https://github.com/openai/openai-node （src/resources 目录）
- 资源类签名（SDK 源码核实）：`export class Evals extends APIResource`，文档注释 "Manage and run evals in the OpenAI platform."；`create(body: EvalCreateParams)` POST `/evals`，参数含 `data_source_config`（数据源配置）与 `testing_criteria`（"A list of graders for all eval runs in this group."），另有 retrieve/update/list/delete 与 `runs` 子资源（发起/管理评测运行）。来源：https://github.com/openai/openai-node/blob/master/src/resources/evals/evals.ts
- 定位：托管在 OpenAI 平台的评测（服务端跑、服务端评分），与 promptfoo（本地跑）互补；教程可作为"云托管 eval"一节。注：platform.openai.com 文档页需登录，未能直接摘录 guide 文案。

### 8.2 LangSmith（TS SDK 完整可用）

- npm 包名是 **`langsmith`**（不带 @langchain scope！registry 曾以 @langchain/langsmith 查询返回 Not Found，正确包名为 langsmith）：最新 **0.10.11**（2026-10-09 发布），描述 "Client library to connect to the LangSmith Observability and Evaluation Platform"。来源：https://registry.npmjs.org/langsmith
- 官方仓库 langchain-ai/langsmith-sdk（`js/` 目录为 TS SDK，仓库 2026-10-10 仍在推送，活跃）。来源：https://github.com/langchain-ai/langsmith-sdk
- 能力（js/README 核实）：`traceable` 包装任意函数/SDK、`wrapOpenAI` 包装 OpenAI SDK、手动 `RunTree` 构造 trace、`Client` 操作数据集与评测（`createDataset`/`createExample`/`listRuns`）、沙箱；环境变量 `LANGSMITH_TRACING`、`LANGSMITH_API_KEY`、`LANGSMITH_PROJECT`。官方 README 最小示例（逐字摘录）：
  ```ts
  import { OpenAI } from "openai";
  import { wrapOpenAI } from "langsmith/wrappers";

  const openai = wrapOpenAI(new OpenAI());

  await openai.chat.completions.create({
    model: "gpt-5.4",
    messages: [{ content: "Hi there!", role: "user" }],
  });
  ```
  来源：https://github.com/langchain-ai/langsmith-sdk/blob/main/js/README.md
- 教程定位：闭源商用平台（无免费自部署），TS SDK 质量高，适合"业界还有谁"对比一节。

## 9. 教程选型建议

**推荐教学主轴：promptfoo（prompt/模型回归评测）+ Langfuse 自部署（全链路追踪与数据集实验）+ autoevals（代码内断言/自建 judge），三者均为开源、无供应商锁定。**

| 角色 | 选型 | 理由 |
|---|---|---|
| 回归评测（CI 门禁） | **promptfoo** | npm 单包、YAML 配置上手快；断言体系从 `contains` 到 `llm-rubric` 平滑升级教学；官方 GitHub Action 直接进 CI；红队是进阶亮点。更新极活跃（0.124.1，2026-10-08）。 |
| 全链路可观测 | **Langfuse 自部署（docker compose）** | 开源可自部署免费、无数据外流顾虑，适合教学环境一次 `docker compose up` 跑通；TS SDK v5 全面 OTel 化，与 AI SDK 7 的 GenAI span 天然互通；数据集/实验/评分把离线评测与线上观测串成闭环；Hobby 云层（50k units/月）也可作零安装备选。 |
| 代码内断言 | **autoevals** | 纯库、框架无关，`Factuality()` 等 scorer 一个函数调用即得 0–1 分，教学"LLM-as-judge 原理"最直观；同时是 Braintrust 平台的 scorer 词汇表，进阶可衔接。 |

**教学路径建议（由浅入深）：**
1. **第 1 站：promptfoo** —— 用 `promptfooconfig.yaml` 对比两个模型的翻译 prompt，`contains` 断言 → `llm-rubric` → GitHub Action 进 CI。（教"评测是什么"）
2. **第 2 站：autoevals** —— 在纯 TS 代码里调 `Factuality`/`Levenshtein`，理解 judge 的输入三元组 `(input, output, expected)` 与 Score 对象。（教"judge 如何工作"）
3. **第 3 站：Langfuse 自部署** —— docker compose 起 Langfuse → `@langfuse/otel` 注册 `LangfuseSpanProcessor` → `observeOpenAI` 包装 OpenAI 调用 → 讲 trace/span/generation 概念 → 建数据集跑实验、把 promptfoo 发现的 bad case 回填数据集。（教"从评测到观测的闭环"）
4. **第 4 站：Vercel AI SDK telemetry** —— `@ai-sdk/otel` 的 `OpenTelemetry` + `registerTelemetry()`（或 Langfuse 的 `@langfuse/vercel-ai-sdk`），顺带教 OTel GenAI 语义约定（提醒仍为 Development 状态）。（教"生产级标准"）

**值得在"生态一览"提及但不作主轴：**
- **DeepEval（npm `deepeval`）**：2026 年官方 TS 版落地（Vitest 集成、`toPass()` 匹配器），思路与教程主轴吻合，但 0.x 阶段，可作"作业/延伸阅读"。
- **Braintrust**：TS Eval API 最顺手、与 autoevals 同门，纯云、免费层小（$10 credits/14 天），适合"商业平台对比"。
- **LangSmith（npm `langsmith`）**：TS SDK 成熟（0.10.11），闭源商用，对比一节提及即可；注意包名不带 scope。
- **OpenAI Evals API（`client.evals`）**：服务端托管评测 + graders，进阶章节介绍"本地 eval vs 托管 eval"的取舍。

**关键避坑点（写进教程）：**
- Langfuse 旧教程/博客里的 `@langfuse/nodejs` 与 `langfuse.trace()` 均为 v3 老用法，2026 年应教 `@langfuse/tracing` + `@langfuse/otel` 的新 API。
- 短生命周期脚本必须 `sdk.shutdown()` / `forceFlush()`，否则丢 trace（官方 FAQ 都在回答这个问题）。
- AI SDK 7 遥测默认开启（注册集成后），旧文档的 `experimental_telemetry` 逐调用开关是 v6 legacy 行为。
- promptfoo 主配置教学用 YAML，测试用例可用 TS 文件；主配置的 `.ts` 写法可用但官方文档化弱。
