# 主干仍新，十四处代码照抄即错

截至 2026-11-13，《AI开发教程-纯TypeScript》的**主干选型仍是当前主流**：DeepSeek / GLM 免费的低成本路线、Vercel AI SDK v7、Zod 4、MCP v2 拆分包、LangGraph / Mastra、promptfoo + Langfuse。2026-10-22 复核时写下的大部分版本区间和国内厂商价格到今天依然成立。但课程**不是"全部最新"**。10-22 之后的三周里出现了一批新变化：Claude Fable 5.2、GPT-6.1 Terra、Gemini 4 Carbon 三款新模型；Kimi K2 停止向新用户开放；Node 26 成为 Active LTS；MCP SDK 升到 2.4、LangGraph 升到 1.7、Langfuse 升到 6.1.1；OpenAI Evals 转为只读；OTel GenAI 规范的内容采集开关定了名。这些让 55 处叙述、版本号或价格过时（P1）。更要紧的是 **14 处 P0**：照抄就会编译失败、运行报错、验收无法通过，或者推荐的是已关停的服务。它们集中在第 7/8/9 章（openai 7.x 联合类型、并行 tool_calls 触发 400、MCP 新握手）、第 12/13 章（LanceDB 泛型、MiniSearch 中文分词、promptfoo RAG 断言）和第 22 章（MemorySaver 无法跨进程恢复）。其中**大多数在 10-22 之前就已存在**，所以根因不是"版本过期"，而是"正文代码从未对着当前类型定义编译过"。对一名从前端转 TypeScript AI 的学员，影响最直接的有三处：第 2 章示例的 Kimi 模型新注册用户已调不了；第 7、8 章手写工具循环在 strict TS 下报红，模型一并行调用工具就 400；第 13 章中文检索的关键词那一路在静默中召回为空。建议用一个工作日修完下文 14 条 P0，并用 `tsc --noEmit` 实测，再分两批处理 P1 和 P2。

> 核查方法与边界：五组并行核查，所有来源的访问日期均为 2026-11-13。依据是 npm registry 原始元数据、jsDelivr/unpkg 上已发布的 `.d.ts`，以及各厂商官方文档、定价页和 GitHub release。**除 Langfuse/OTel 依赖解析做过一次 `npm install --package-lock-only` 实测外，没有安装或运行任何课程代码**；下文"TS 报错"的结论来自对类型定义的静态阅读。课程文件没有被修改。同日的 `research/R10-全课程错误审计-2026-11-13.md` 从"正确性与一致性"角度做了另一份审计，与本报告有交集（如第 5 章 `conversationId`、第 7 章 openai 7 类型）。维护时以两份清单的并集为准，注意别重复修改。

## 十四处 P0 都在代码里，不在价格表里

先说好消息。课程主线依赖的价格**一处没变**：DeepSeek flash 分时价输入 ¥1/¥2、输出 ¥4/¥8，命中缓存 ¥0.02/¥0.04 ([DeepSeek 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing))；GLM-4.7-Flash 与 GLM-4.6V-Flash 仍完全免费 ([智谱定价](https://docs.bigmodel.cn/cn/guide/start/pricing))；硅基 `BAAI/bge-m3` 与 `bge-reranker-v2-m3` 仍免费 ([SiliconFlow](https://siliconflow.cn/pricing))。README 里"全程 API 花费 ¥50-150"的预算依旧可信。附录 B9 的版本快照用的是 x 区间写法（`ai 7.0.x`、`@ai-sdk/* 4.0.x`、`zod 4.6.7`、`next 16.4.x`、`pnpm 12.x`），这些区间也都还对；10-22 到 11-13 之间 `ai` 发了 48 个补丁，全部是 Patch Changes ([ai CHANGELOG](https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md))。

坏消息是，真正会让学员卡住的问题几乎都出在**代码与当前类型定义不一致**上，而这正是"核版本号"这种复核方式抓不到的。`openai` 7.x 把 `ChatCompletionMessageToolCall` 定义成 function 与 custom 两种调用的联合类型，custom 成员没有 `function` 字段，所以第 7、8 章直接写 `call.function.name` 会报 TS2339 ([openai@7.55.0 completions.d.ts](https://cdn.jsdelivr.net/npm/openai@7.55.0/resources/chat/completions/completions.d.ts))。LanceDB 的 `Table` 和 `openTable` 都**不是泛型**，第 12 章的 `Table<Chunk>`、`openTable<Chunk>` 会分别报 TS2315 和 TS2558 ([lancedb table.d.ts](https://cdn.jsdelivr.net/npm/@lancedb/lancedb@0.41.0/dist/table.d.ts))。AI SDK 的静态 `ToolUIPart` 上没有 `toolName` 字段，第 20 章的 `ToolCard` 编译不过；正确做法是改用 SDK 导出的 `getToolName()` ([AI SDK chatbot tool usage](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-tool-usage))。`marked.parse` 的返回类型是 `string | Promise<string>`，直接传给 `cheerio.load` 也通不过 strict 检查 ([marked 18.2.0 d.ts](https://cdn.jsdelivr.net/npm/marked@18.2.0/lib/marked.d.ts))。

第二类 P0 是**课程自身的逻辑矛盾**。第 8 章只执行 `tool_calls[0]`，却把含全部调用的 assistant 消息写进了历史。OpenAI 与 Anthropic 都要求每个调用 id 有且只有一条结果，所以模型一旦并行调用多个工具，下一轮请求就会 400 ([OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)；[Anthropic tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls))。第 22 章用纯内存的 `MemorySaver`，验收却要求"kill 进程后恢复"，这一步必然失败 ([LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts))。第三类是**指向已不存在或已关停的东西**：promptfoo 没有 `context-precision` 断言 ([promptfoo expected-outputs](https://www.promptfoo.dev/docs/configuration/expected-outputs/))；OpenAI Evals 于 10-31 起只读、11-30 关停 ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations))；`kimi-k2.6` 自 10-31 起不再对新注册用户开放 ([Kimi 定价](https://platform.kimi.com/docs/pricing/chat))。

## 新模型抬高了价格表顶端，学员的月预算没变

10-22 之后，四家厂商发布了改写价格表的新品。Anthropic 于 11-09 发布 **Claude Fable 5.2**（`claude-fable-5-2`，$8/$40），它取代 Fable 5.1（$10/$50）进入官方"Latest models"表，缓存读取同为 0.025x ([Claude Models overview](https://platform.claude.com/docs/en/models/overview)；[Claude Pricing](https://platform.claude.com/docs/en/about-claude/pricing))。OpenAI 于 10-26 发布 **GPT-6.1 Terra**（$1/$5），补上了 Sol（$2/$10）与 Luna（$0.10/$0.50）之间的中档 ([OpenAI Changelog](https://developers.openai.com/api/docs/changelog))。课程使用的 GPT-6 家族名称、模型 ID、价格以及 1.05M / 128K 规格本身都经官方核实无误 ([OpenAI Models](https://developers.openai.com/api/docs/models))。Google 于 10-28 发布 **Gemini 4 Carbon**，官方模型页称它是"strongest reasoning model"，价格与 Argon 相同，但官方博客说明它分阶段开放、先面向网络安全防御者 ([Gemini 4 Carbon 博客](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/))。Kimi 于 10-24 发布 K3.1 Pro（¥13/¥68），同时公告 **K2 系列 10-31 起停止向新注册用户开放、12 月底全部下线** ([Kimi K3.1 Pro](https://www.kimi.com/news/kimi-k3-1-pro)；[Kimi 定价](https://platform.kimi.com/docs/pricing/chat))。

这些变化对学员的实际影响比看上去小。按输出价对比 DeepSeek flash 空闲输出 ¥4，"旗舰贵 18-90 倍"这个区间**仍然成立**：下限是 Sonnet 5.5 / GPT-6.1 Sol 的 18x，上限是 GPT-6 Astra 的 90x。变化在区间内部：Fable 5.2 降到 72x，不能再与 Astra 并列写成 90x；新的 Terra 约 9x，比 Sol 更适合当"中档对照"。真正的硬伤只有一处：第 2 章给新手的 Kimi 示例 `kimi-k2.6` 在 10-31 之后注册的账号上已经不可用。另有一处说法缺乏依据。附录 B 写"GPT-5.2 已进入关停流程"，但官方关停表里只有 `gpt-5.2-chat-latest` 和 `gpt-5.2-codex` 两个条目，没有基础模型 `gpt-5.2` ([OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations))。

比价格更值得改的是课程的核心承诺"一套代码 + 切 baseURL"，它现在**需要加前提**。对国内厂商、Gemini 兼容层和 OpenRouter，这个承诺照旧成立。但 OpenAI 自家旗舰已经变了：GPT-6 Astra / 6.1 Sol / 6.1 Terra 支持 Chat Completions，**工具调用却只能走 Responses API**；推理强度不是 `none` 时，还必须去掉 `temperature` 和 `top_p` ([OpenAI: Using the latest model](https://developers.openai.com/api/docs/guides/latest-model))。第 2 章说切到 OpenAI 原生端点"只需把 max_tokens 换名"，这已经不够了。Anthropic 方面，课程说"唯一例外是 Anthropic"，同样已经过时。Anthropic 现在有官方的 OpenAI SDK 兼容端点，但限制很多：Claude 4.7 及以后的模型 `temperature` 小于 1 直接返回 400，`json_object` 返回 400，也不支持缓存 ([Anthropic OpenAI SDK compatibility](https://platform.claude.com/docs/en/api/openai-sdk))。原生 SDK `@anthropic-ai/sdk` 1.0 起默认使用 API 版本 2026-10-21，发送 `temperature`、`top_p`、`top_k` 中的任何一个都会 400 ([Anthropic 2026-10-21 迁移指南](https://platform.claude.com/docs/en/api/migration-2026-10-21))。缓存也一样：OpenAI 的缓存读价实际在 5%–10% 之间，还另收写入费 ([OpenAI Pricing](https://developers.openai.com/api/docs/pricing))；**Claude 不会自动缓存**，必须显式加 `cache_control` ([Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))。这意味着第 17 章练习"只重排前缀就能省钱"放到 Claude 上，命中率会是 0。

多模态部分有两处上一轮漏核，公告时间都早于 10-22。`whisper-1` 于 08-26 宣布弃用，2027-02-26 关停，官方推荐改用 `gpt-transcribe` ([OpenAI Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text))。`tts-1`、`gpt-4o-mini-tts` 于 10-01 宣布弃用，2027-01-06 关停，官方迁移目标 `gpt-realtime-2.1-mini` 只能走 Realtime API ([OpenAI Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech))。第 21 章写的"Whisper API（稳定）"因此不再成立。

## Node 26 接棒，AI SDK v7 的写法依然有效

工具链里最大的一处事实错误在 Node。按 Node 官方发布计划，**Node 24 已于 10-20 进入维护期**，支持到 2028-04-30；**Node 26 已于 10-28 成为 Active LTS** ([nodejs/Release schedule.json](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json))。winget 的 `OpenJS.NodeJS.LTS` 包现在装的是 26.13.x ([winget-pkgs](https://github.com/microsoft/winget-pkgs/tree/master/manifests/o/OpenJS/NodeJS/LTS))，所以第 2 章的"应输出 v24.x.x"对新安装的学员是错的。不过课程技术栈在 Node 26 上不会出问题：AI SDK 7 在 Node 22、24、26 上都经过测试 ([AI SDK 7 迁移指南](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0))，pnpm 12 也支持 Node 26 ([pnpm installation](https://pnpm.io/installation))。所以这里要改的是叙述，不是代码。顺带一提，同一份 AI SDK 迁移指南写"Node 22 已于 2026-04-30 结束维护"，这与 Node 官方计划（22 维护到 2027-04-30）矛盾。可见官方文档之间也要交叉核对。

TypeScript 仍是 7.0.2 稳定版，7.1 Beta 于 10-20 发布。TS 7 把 `types` 的**编译器默认值**改成了 `[]` ([Announcing TypeScript 7.0](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/))，第 2 章把它解释成 `tsc --init` 模板的产物，不够准确。Next.js 16.4.6（11-09）开始在 `next start` 自托管时自动压缩 Route Handler 响应 ([v16.4.6 release](https://github.com/vercel/next.js/releases/tag/v16.4.6))，第 5 章的 SSE 流因此可能被缓冲。这一点**尚未实测**，只能先作为防御性提示写进常见坑。GitHub Actions 已于 09-23 移除 runner 上的 Node 20 ([GitHub changelog](https://github.blog/changelog/2026-09-23-node-20-is-no-longer-available-in-github-actions))，第 15 章和第 19 章的 `actions/checkout@v4`、`setup-node@v4`、`pnpm/action-setup@v4` 都已落后，`node-version: 22` 也与课程的 Node 主线不一致。

AI SDK v7 方面，课程的 API 写法**全部正确**：`instructions`、`onEnd`、`isStepCount`、`Output.object`、`tool({ inputSchema })`、`ToolLoopAgent`、异步的 `convertToModelMessages`、`toUIMessageStream` + `createUIMessageStreamResponse`、四态 `status`，都与官方迁移指南和 7.0.170 的类型定义一致 ([AI SDK 7 迁移指南](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0))。10-22 之后的补丁带来了几处需要留意的新行为 ([ai CHANGELOG](https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md))。一是新增 `interrupted` 结束原因，按 FinishReason 写穷举 switch 的代码会因此编译失败，尽管这只是 patch 版本。二是新增 `onStepError`。三是 `dataPartSchemas` 开始真正校验。四是 7.0.155 起不再在运行时校验 `messages`。此外有一项 7.0.0 起就有的安全修正一直没反映到课程里：`toUIMessageStream` 默认**不再把服务端异常透传给前端**。第 5 章错误表承诺"把限流错误写进流、前端展示"，要做到就得显式写 `onError` 映射。附录 B 还有一处归属错误：它把 `DefaultChatTransport` 列为"v7 改名"，但官方 useChat 文档写明 transport 架构是 **v5** 引入的 ([useChat reference](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat))，第 5 章正文对此写得正确。

## 协议与 LLMOps 层，一个月改了一轮

协议层的变化最考验课程措辞。MCP 当前规范是 2026-07-28 版，课程把它概括为"无状态 + 每请求版本协商 + server/discover"，这个概括是对的。但规范同时移除了会话、GET 推送流和 SSE 断点续传，把 sampling、elicitation、roots 改成了 MRTR，并把 Roots、Sampling、Logging 列为 Deprecated ([MCP 2026-07-28 Key Changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog))，课程都没有提。最关键的是第 9 章那句"v2 SDK 已封装这些细节，本章代码无需改动"，它**与官方原文相反**。官方说，用 `server.connect(new StdioServerTransport())` 手工连接的服务端"still compiles, but a server started that way only serves 2025-era clients"，新写法是 `serveStdio(createServer)` ([MCP Build a server](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-server))。客户端 `Client` 的版本协商默认是 `'legacy'`，要走新协议，必须显式传入 `versionNegotiation: { mode: "auto" }` ([MCP Build a client](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-client))。课程代码今天还能跑，是因为 Claude Code 等宿主会回退到 2025 年的握手；随着宿主切换到新协议，这种依赖会变成隐患。框架这边，LangGraph 1.7.0（11-05）起才允许 `Command({ resume: false })` 这类 falsy 值传到 `interrupt()`，之前的版本会抛 `EmptyInputError` ([langgraph-core CHANGELOG](https://raw.githubusercontent.com/langchain-ai/langgraphjs/main/libs/langgraph-core/CHANGELOG.md))。Mastra 官方明文规定"Memory **requires** a storage provider"，第 10 章的示例却没有配置 storage ([Mastra Memory](https://mastra.ai/docs/memory/overview))。

可观测这一块，课程"必须把 OpenTelemetry 锁在 2.x"的结论**到今天仍然成立**。11-13 的实测显示，不锁版本时 npm 依旧报 ERESOLVE。但锁定的版本号要更新。Langfuse 6.1.1 把 exporter 的 peer 依赖收紧到 `<0.300.0`，官方说明是"stay on the OpenTelemetry SDK 2.x line" ([langfuse-js releases](https://github.com/langfuse/langfuse-js/releases))。OTel 官方也于 11-09 继续发布了 2.x 维护线的 2.12.1 / 0.223.1，并打上 npm dist-tag `latest-2` ([opentelemetry-js releases](https://github.com/open-telemetry/opentelemetry-js/releases))，所以课程"0.223.0 是 2.x 线最后一版"的说法已被推翻。OTel GenAI 语义约定仍处于 Development 状态，过去一个月里改动不少。10-26 起，内容采集开关正式命名为 `OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT`，默认值 `NO_CONTENT` ([gen-ai-spans.md](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md))。`gen_ai.tool.call.arguments` 是 `execute_tool` span 上的 Opt-In 属性，课程写成"事件属性、不是 span 属性"，说反了 ([execute-tool.md](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/execute-tool.md))。还要注意，AI SDK 7 的遥测**默认记录输入与输出** ([AI SDK telemetry](https://ai-sdk.dev/docs/ai-sdk-core/telemetry))，这与课程"内容默认不采集"的说法正好相反，接入 Langfuse 后用户 prompt 会原样进入 trace。

评测、安全与 AI 编程工具三处，也各有一条需要补充或纠正的事实。评测方面，OpenAI Evals 平台于 06-03 宣布弃用，10-31 起只读，11-30 关停，官方迁移指引直接指向 promptfoo ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations))；promptfoo 自己则于 03-09 宣布被 OpenAI 收购，并承诺继续开源 ([promptfoo blog](https://www.promptfoo.dev/blog/promptfoo-joining-openai/))。安全方面，OWASP LLM Top 10 仍是 2025 版，但 OWASP 早在 2025-12-09 就发布了 **Top 10 for Agentic Applications for 2026** ([OWASP GenAI](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/))，一门以 Agent 为主线的课程不该缺这一块。协议方面，A2A 的 v1.0（03-12）、加入 AAIF（08-17）、150+ 组织支持这些事实都有一手来源，唯独"Growth Stage"这个标签在 AAIF 的公告和项目页中都找不到 ([AAIF: A2A joins AAIF](https://aaif.io/md/blog/a2a-joins-aaif))。AI 编程工具有四处要纠正。第一，第 2 章说"官方已标注 npm 安装为 deprecated"，但官方文档仍把 npm 列为受支持的安装方式 ([Claude Code setup](https://code.claude.com/docs/en/setup))。第二，第 6 章的"单个 Skill 预算约 5,000 token"是误读：官方的写作建议是 SKILL.md 控制在 500 行以内，5,000 token 指的是上下文压缩后为每个已调用 Skill 保留的量 ([Claude Code Skills](https://code.claude.com/docs/en/skills))。第三，Claude Code 自 v2.1.277 起原生读取 AGENTS.md ([How Claude remembers your project](https://code.claude.com/docs/en/memory))，Cursor 也直接读取 AGENTS.md，而且四种规则类型已经改名 ([Cursor Rules](https://cursor.com/docs/rules))，课程对这些都没有提及。

## 中文 RAG 链路有三处默认值静默失效

第 12、13 章最隐蔽的问题是：一批**为英文设计的默认值**用在中文语料上，不报错，只是效果悄悄归零。第一处是 MiniSearch。它默认按空白和标点切词 ([minisearch 7.2.0 源码](https://cdn.jsdelivr.net/npm/minisearch@7.2.0/dist/es/index.js))。核查时在本机跑了这条正则："本公司支持 7 天无理由退货"被切成"本公司支持""7""天无理由退货"，查询"退货政策是什么"整句成为一个词，两边**一个词都对不上**。混合检索里的关键词一路因此召回为空，课程却仍在讲"专有名词召回率提升"。换成 `Intl.Segmenter("zh", { granularity: "word" })` 后就能命中。同一段代码还有两个问题：`addAll` 遇到重复 id 会抛错，与验收要求的"可重复跑"冲突；索引只存在内存里，而 `pnpm ingest` 和 `pnpm dev` 是两个进程，服务进程拿到的是空索引。第二处是切片器。`RecursiveCharacterTextSplitter` 的默认分隔符是 `["\n\n", "\n", " ", ""]`，**根本没有句子级**，长度也按字符计 ([text_splitter.ts](https://raw.githubusercontent.com/langchain-ai/langchainjs/main/libs/langchain-textsplitters/src/text_splitter.ts))；中文没有空格，换行之后就直接按字硬切，课程"段落→句子→字符"的描述并不成立。第三处是 LanceDB 全文检索，它的默认分词器 `simple` 对中文同样无效 ([lancedb indices.d.ts](https://cdn.jsdelivr.net/npm/@lancedb/lancedb@0.41.0/dist/indices.d.ts))。

LanceDB 部分还有两个概念错误。其一，没有建向量索引时，LanceDB 做的是**精确暴力 kNN**，而不是课程注释里写的"ANN 检索（不扫全库）"；官方甚至说 10 万行以内一般不需要索引。其二，未建索引时默认距离是 **L2**，不是余弦，所以"余弦相似度 = 1 − `_distance`"只有在显式设置 `distanceType("cosine")` 之后才成立 ([LanceDB vector search](https://docs.lancedb.com/search/vector-search.md))。另外，0.41.0（10-29）把 apache-arrow 的 peer 范围放宽到 `<22` ([lancedb v0.41.0](https://github.com/lancedb/lancedb/releases/tag/v0.41.0))。在此之前，0.40 与当前的 arrow 21 存在 peer 冲突，所以安装命令应锁 `^0.41`。

Rerank 一节的"三家 API 同构、一个适配器通吃"是**错的**。Voyage 的参数叫 `top_k`，响应数组叫 `data` ([Voyage reranker API](https://docs.voyageai.com/reference/reranker-api))；Cohere 用 `/v2/rerank`，请求体里没有 `return_documents` ([Cohere rerank v2](https://docs.cohere.com/reference/rerank))。课程代码把路径硬写成 `/v1/rerank` 并解构 `results`，切到 Voyage 时拿到的是 `undefined`。Cohere 已推出 Rerank 5（`rerank-v5.0-pro/fast`，32K），课程主推的 `rerank-v3.5` 只支持 4K ([Cohere rerank models](https://docs.cohere.com/docs/rerank))。不过"Rerank 5 改为按 token 计费"目前只有二手报道，**本轮未能证实**。Qdrant 1.20（10-22）起可以在服务端直接做 BM25 文本查询 ([qdrant releases](https://github.com/qdrant/qdrant/releases))，而硅基的 OpenAI 兼容 embedding 接口拿不到 bge-m3 的稀疏输出 ([硅基 embeddings API](https://docs.siliconflow.cn/docs/api/embeddings-post))，所以第 12 章的 Qdrant 示例应改走服务端 BM25。百炼 `text-embedding-v4` 每次请求最多 10 条 ([百炼向量模型](https://help.aliyun.com/zh/model-studio/embedding))，课程代码按 64 条一批发送会超限。评测方面，promptfoo 的 `context-faithfulness` **必须提供 `context`** ([promptfoo context-faithfulness](https://www.promptfoo.dev/docs/configuration/expected-outputs/model-graded/context-faithfulness/))；`context-recall` 的 `value` 应写成标准答案陈述，不能写成一条指令 ([promptfoo context-recall](https://www.promptfoo.dev/docs/configuration/expected-outputs/model-graded/context-recall/))。第 13 章的 YAML 两处都写错了，所以验收"context-recall ≥ 0.8"无从谈起。

**替换块 12-1**（L121-164；按 0.41 的 `.d.ts` 编写，未实机运行；旧库请删除 `./data/lancedb` 后重建，否则种子行还在）：

```ts
// lib/vectorstore.ts —— LanceDB 封装（@lancedb/lancedb 0.41.x）
import * as lancedb from "@lancedb/lancedb";
import { Field, FixedSizeList, Float32, Schema, Utf8 } from "apache-arrow";
import { embed } from "./embed";

const DIM = Number(process.env.EMBED_DIM ?? 1024);   // 与模型绑定！bge-m3=1024, openai-small=1536

export interface Chunk { id: string; text: string; source: string; vector: number[] }

const schema = new Schema([
  new Field("id", new Utf8(), false),
  new Field("text", new Utf8(), false),
  new Field("source", new Utf8(), false),
  new Field("vector", new FixedSizeList(DIM, new Field("item", new Float32(), true)), false),
]);

export class VectorStore {
  private table: lancedb.Table | null = null;          // Table 不是泛型

  async init(path = "./data/lancedb") {
    const db = await lancedb.connect(path);            // 目录即数据库（也支持 s3://）
    // 幂等：已存在就直接打开（existOk），不存在才按 schema 建空表——不再需要「种子行」
    this.table = await db.createEmptyTable("chunks", schema, { mode: "create", existOk: true });
  }

  async add(chunks: Omit<Chunk, "vector">[]) {
    const vectors = await embed(chunks.map((c) => c.text));
    await this.table!.add(chunks.map((c, i) => ({ ...c, vector: vectors[i] })));
  }

  async search(query: string, topK = 5) {
    const [qv] = await embed([query]);
    const rows = await this.table!
      .vectorSearch(qv)                                // 未建索引 = 精确 kNN（全扫）；约 10 万行级再建索引
      .distanceType("cosine")                          // 默认是 l2！cosine 时 _distance = 1 - 余弦相似度
      .select(["id", "text", "source", "_distance"])
      .limit(topK)
      .toArray();
    return rows as (Omit<Chunk, "vector"> & { _distance: number })[];
  }
}
```

// lib/rerank.ts —— 三家「形似而不同构」：参数名、路径、响应字段各不相同
const CFG = {
  siliconflow: { url: "https://api.siliconflow.cn/v1/rerank", model: "BAAI/bge-reranker-v2-m3", topKey: "top_n" },
  cohere:      { url: "https://api.cohere.com/v2/rerank",     model: "rerank-v5.0-fast",        topKey: "top_n" }, // v2 无 return_documents
  voyage:      { url: "https://api.voyageai.com/v1/rerank",   model: "rerank-3",                topKey: "top_k" }, // 参数叫 top_k
} as const;
type Provider = keyof typeof CFG;

export async function rerank(query: string, documents: string[], topN = 5) {
  const provider = (process.env.RERANK_PROVIDER ?? "siliconflow") as Provider;
  const { url, model, topKey } = CFG[provider];
  const res = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.RERANK_API_KEY}` },
    body: JSON.stringify({ model: process.env.RERANK_MODEL ?? model, query, documents, [topKey]: topN }),
  });
  if (!res.ok) throw new Error(`rerank(${provider}) ${res.status}: ${await res.text()}`);
  const json = await res.json();
  const hits = (json.results ?? json.data) as { index: number; relevance_score: number }[]; // Voyage 返回 data
  return hits;                                                                               // 按相关度降序，index 指回 documents
}

## 结论

这轮核查改变的是对"课程为什么会过时"的判断。课程的版本快照机制本身是有效的：x 区间写法挡住了三周里几十个补丁版本的漂移，国内价格也一处没变。真正的风险在快照覆盖不到的两层。一层是**类型层**：openai 7.x 的联合类型、LanceDB 的非泛型 `Table`、AI SDK 的 `ToolUIPart`，都在版本号"没变大版本"的前提下改了签名。另一层是**语料层**：为英文设计的分词与切片默认值放进中文 RAG 后静默失效，不报错，只是让检索质量归零。所以复核流程里该增加两道门：一是把正文代码块抽成文件跑 `tsc --noEmit`（R10 已证明可行）；二是一张"中文语料默认值"检查表，覆盖分词器、分隔符、FTS tokenizer 和距离度量。对学员而言，值得长期押注的是那些在这轮变化中**没有动**的概念：每个 tool_call id 必须有结果、HITL 需要持久化 checkpointer、RRF 只看名次、先评测后优化。会变的是模型名、价格和 Development 状态规范里的属性名，课程应教学员"去哪里核"，而不是把它们当成记忆点。

下一轮复核的时间点也已经确定。11-30 有三件事：OpenAI Evals 彻底关停，GPT-5.6 Sol 促销截止，Gemini 4 Argon / Carbon 次日起涨到 $4/$20，旗舰倍数里的 Gemini 一档会从 18x 变成 36x。12-11 o3 与 gpt-5 系关停；12 月底 Kimi K2 全部下线。2027 年 1 月有两个节点：1 日 Gemini Flash 价格翻倍，6 日 OpenAI TTS 关停。此外有几项进展值得跟踪：TypeScript 7.1 RC 预计 11 月下旬发布；Hono 5 已进入 RC；Langfuse 何时支持 OTel 3 还没有路线图。建议把下一次时效复核排在 **2026-12-01 至 12-15 之间**，先核价格表与 B9 快照，再看 Langfuse 是否放开 OTel 3 的锁定。
