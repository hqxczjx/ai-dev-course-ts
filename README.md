# AI 开发完整教程（纯 TypeScript 版）

> **一门不学 Python 的 AI 开发课**——用你已有的 TypeScript / Node.js / React 能力，从零掌握 2026 年 AI 应用与 Agent 开发的全部核心内容，直达「AI 方向前端 / TS 系 Agent 工程师」岗位要求。

- **适用人群**：有 1 年以上前端开发经验（TS / React 或 Vue / Node 基础），想转型 AI 应用开发的工程师
- **学习目标**：只依赖本教程，掌握 AI 应用开发的完整技能树，并产出 **3 个可上线的作品集项目**
- **技术底线**：全程 TypeScript / Node.js，**不要求学 Python**（第 0 章解释为什么这条路成立）
- **事实基础**：教程中的生态工具、版本、价格于 **2026-11-13 第三轮联网复核**（初版 2026-10-11，第二轮 2026-10-22）。本轮核查报告见 [时效核查报告](reports/TS课程技术时效核查%202026年11月.md)，逐条底稿见 `research_notes/`，全课程代码审计见 [`research/R10`](research/R10-全课程错误审计-2026-11-13.md)
- **可运行代码**：核心章节的代码在 [`code/`](code/README.md) 里有完整实现，严格模式下能编译，并带离线测试；不需要 API key，`pnpm check` 一条命令就能验证
- **岗位依据**：课程大纲由 215 个真实岗位（BOSS直聘 103 + V2EX 112）交叉验证得出（岗位调研原文是课程之外的配套文档，没有收入本目录）

## 二、为什么「不学 Python」是成立的

这是本教程最重要的定位决策，依据有三层：

**1. 市场证据**。215 个岗位调研显示：TS/JS 是与 Python 并列的最高频语言之一，且是 **Agent Runtime / CLI / SDK / AI Coding 工具链方向的事实标准**。「AI 方向前端」「TS 系 Agent 开发」「AI 全栈」三类岗位（合计约 45%）对 TS 的偏好不亚于甚至高于 Python；V2EX 上存在纯 TS 栈的 Agent 岗位。市场明确背书「前端也可以做 AI」（华为云 JD 原话）。

**2. 生态证据**。AI 应用开发所需的每一个环节，TS 生态在 2026 年都已齐备：

| 你在 JD 里看到的（Python 世界） | 本教程教你的（TS 世界） |
|---|---|
| openai / anthropic SDK | 官方均有 TS SDK，且 **Vercel AI SDK** 一套统一多家 |
| FastAPI | Node.js + Hono / Next.js API Routes |
| Pydantic | **Zod**（结构化输出与校验） |
| LangChain / LangGraph | **LangChain.js / LangGraph.js**（官方同源） |
| LlamaIndex | LlamaIndex.TS |
| Chroma / Qdrant 客户端 | Qdrant / Chroma 官方 JS 客户端、LanceDB（嵌入式） |
| Ragas / DeepEval | **promptfoo**（TS 原生）+ autoevals + Langfuse Evals |
| Langfuse Python SDK | Langfuse **TS SDK**（功能对等） |
| mem0 / Letta | Mastra Memory / 自建分层记忆（第 14 章手写） |
| CrewAI / AutoGen | Mastra 多 Agent / LangGraph.js 编排 / OpenAI Agents SDK（JS 版） |
| Jupyter 实验 | Vitest + 脚本 + evals（工程口径，更贴近生产） |

**3. 学习效率证据**。你的 TS/React/Node 存量是真实资产：异步流式（SSE 本来就是前端技术）、组件化、工程化、npm 生态——在「AI 方向前端」「Agent Runtime」这两类目标岗位上直接变现。补一门新语言的沉没成本，换成直接在生产级项目里堆深度。

> **诚实说明**：部分岗位 JD 写了「精通 Python」，这些岗（画像 A，约 30%）不是本教程的直投目标。但你在本教程第 10、13 章会学到 LangGraph 与 RAG 的**通用概念**，这些概念跨语言不变——将来真需要 Python，一两周即可迁移（附录 B 给了迁移路径）。另外第 6 章的 AI 编程工具方法论会教你如何跨越语言边界，这本身就是 JD 里的加分能力。

## 四、如何使用本课程

**每章的固定结构**（教学设计说明）：

```
📋 本章目标        —— 3-5 条可检验的能力，学完逐条对照
编号小节          —— 概念讲解与代码实战交织：是什么 / 为什么 / 怎么写（完整代码在 code/）
⚠️ 常见坑          —— 真实踩坑记录，先看可以省几小时
✍️ 动手练习        —— 从模仿到独立完成的阶梯任务
🧠 自测清单        —— 合上书回答（检索练习，比重读有效 3 倍）
🔗 延伸阅读        —— 官方一手资料（只列最高质量的 2-3 个）
```

（第 22 章是毕业项目，「动手练习」就是项目任务本身，另加「交付证据」清单与验收命令。）

**学习方法**（第 0 章详细展开）：

- **不要通读**。每章按「目标 → 代码实战 → 练习」走，概念卡住再回头看讲解
- **先做后看**。练习先自己写 30 分钟再看参考思路
- **自测必须合上文档**。能复述才算学会，复述不出来的回来重学
- **从第 2 章起全程用 AI 编程工具写代码**——本教程教你 AI 开发，也要求你用 AI 方式开发
- **先离线证明逻辑，再真实调用验收**（见下）

**配套代码 `code/` 与两层验证**：

```bash
cd code && pnpm install   # Node 24/26 + pnpm 12；构建脚本审批已写在 code/pnpm-workspace.yaml
pnpm check                                       # 类型检查 + 全部离线测试：不需要 API key，不花钱
```

`code/` 里是第 02、04、07、08、11、12–13、17、18 章核心代码的完整实现，正文代码块和其中的文件一一对应（对照表见 [code/README.md](code/README.md)）。验证分两层，缺一不可：

1. **离线测试（FakeModel）**：按脚本给出模型回复，确定地复现坏 JSON、并行工具调用、死循环、越权访问、崩溃后重复下单等失败路径，证明**程序逻辑**是对的。
2. **真实模型评测集（第 15 章）**：证明**模型 + 提示词 + 检索**的效果，报告里要公开失败用例，而不是只报一个总分。

每做一道练习，先写一条离线测试，再写实现；改代码之前先跑 `pnpm check`，改完再跑一次。

**时间规划**：

| 节奏 | 周期 | 里程碑 |
|---|---|---|
| 在职（每周 10-15h） | 约 7 个月（按上面的周次） | 第 2 月项目 1 上线 → 第 4 月项目 2 上线 → 第 7 月项目 3 上线并开始投递 |
| 全职（每周 35h+） | 约 4 个月 | 同上，各提前约一半时间 |

**费用预算**：教程全程 API 花费可控制在 **¥50-150**（用 DeepSeek/Qwen 等低价或免费额度练手，关键节点用旗舰模型验证；第 2 章讲预算控制与费用监控，并有「每日 token 预算」练习）。
