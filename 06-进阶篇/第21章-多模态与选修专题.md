## 21.1 图像理解（VLM）：给模型装上眼睛

视觉模型的接入与对话 API 同构——消息里多一种 content 类型：

```ts
// multimodal/vlm.ts —— 图像理解的统一姿势（OpenAI 兼容格式，多数厂商支持）
// 依赖：pnpm add openai；client 就是第 2 章那个带 baseURL 的实例
import OpenAI from "openai";
import { readFile } from "node:fs/promises";

const client = new OpenAI({ apiKey: process.env.API_KEY, baseURL: process.env.BASE_URL });
const buf = await readFile("./screenshot.png");   // 换成你要分析的图片

const res = await client.chat.completions.create({
  model: process.env.VLM_MODEL ?? "deepseek-flash", // 默认配置（DeepSeek）下 deepseek-flash 就能看图（v4-pro 不能）；
                                    // 想零成本：BASE_URL 换智谱用 glm-4.6v-flash（免费），或 Gemini Flash 免费层（2026-11 复核）
  messages: [{
    role: "user",
    content: [
      { type: "text", text: "这张图里的报错是什么？给我修复步骤" },
      { type: "image_url", image_url: { url: `data:image/png;base64,${buf.toString("base64")}` } },
    ],
  }],
});
console.log(res.choices[0]?.message.content);
```

三个高价值应用（都比「看图说话」更工程）：**截图诊断**（用户拍屏报错→VLM 定位→结合第 13 章 RAG 查文档给方案）；**文档理解**（扫描件/表格的 OCR 替代——传统 OCR 提字，VLM 直接「理解」结构）；**多模态 RAG**（图文混合切片入向量库，图用 VLM 生成描述文本编码）。安全提醒：图像是间接注入的又一载体（图里嵌文字指令），第 18 章防线同样适用。

## 21.2 语音：ASR 与 TTS

```
语音对话完整链路（全 TS 可实现）：
麦克风 → Web Audio 采集 → ASR API（语音转文字）→ 你的对话/Agent 管线
                                              → TTS API（文字转语音）→ 播放
```

- **ASR（语音转文字）**：OpenAI 现在推荐 `gpt-transcribe`（`/v1/audio/transcriptions`，文件上传式）；`whisper-1`、`gpt-4o-transcribe`、`gpt-4o-mini-transcribe` 已弃用，2027-02-26 关停；实时流式转写用 `gpt-live-transcribe`（走 Realtime API）。其他选择：Gemini `gemini-3.5-transcribe`、硅基流动免费的 `FunAudioLLM/SenseVoiceSmall`（接口路径与参数以各家文档为准）（2026-11 复核）
- **TTS（文字转语音）**：OpenAI 的 `tts-1` / `tts-1-hd` / `gpt-4o-mini-tts` 已弃用，2027-01-06 关停；官方迁移目标 `gpt-realtime-2.1-mini` 只走 Realtime API，**不支持** `/v1/audio/speech`。Gemini 仍有独立 TTS 模型（`gemini-3.8-flash-tts`，有免费层，调用方式以其文档为准）；Ollama 本地也提供 `/v1/audio/speech` 兼容端点（2026-11 复核）。对话场景注意**流式 TTS**（分段合成边放）才是对话级延迟
- **体验关键**不在模型在工程：打断处理（用户开口立刻停播）、VAD（静音检测判断说完了）、回声消除——这些前端/客户端技能又是你的主场

文件上传式的最小代码。DeepSeek 自 2026-11-13 起提供独立的 ASR / TTS / OCR 接口（如 `POST /v1/tools/asr`），但不是 OpenAI 兼容的 `/v1/audio/*` 格式，也没有生图（2026-11 复核）；本节代码走 OpenAI 兼容端点，所以多模态单独配一组环境变量：`MEDIA_API_KEY` / `MEDIA_BASE_URL`（任一提供 OpenAI 兼容语音端点的厂商），模型名放 `ASR_MODEL` / `TTS_MODEL`：

```ts
// multimodal/asr.ts —— 语音转文字（文件上传式）
import OpenAI from "openai";
import { createReadStream } from "node:fs";

// DeepSeek 的语音接口不是 OpenAI 兼容格式：本节单独配一组 MEDIA_* 环境变量（OpenAI 兼容端点）
const media = new OpenAI({ apiKey: process.env.MEDIA_API_KEY, baseURL: process.env.MEDIA_BASE_URL });

const res = await media.audio.transcriptions.create({
  file: createReadStream("./question.mp3"),
  model: process.env.ASR_MODEL ?? "gpt-transcribe",  // OpenAI 推荐的转写模型；whisper-1 已弃用
});
console.log(res.text);
```

```ts
// multimodal/tts.ts —— 文字转语音，写成 mp3
import OpenAI from "openai";
import { writeFile } from "node:fs/promises";

const media = new OpenAI({ apiKey: process.env.MEDIA_API_KEY, baseURL: process.env.MEDIA_BASE_URL });
const model = process.env.TTS_MODEL;                  // 填你所选厂商的 TTS 模型名（见上方说明）
if (!model) throw new Error("先在 .env 里配置 TTS_MODEL");

const speech = await media.audio.speech.create({
  model,
  voice: process.env.TTS_VOICE ?? "alloy",            // 音色名各家不同
  input: "您的订单已发货，预计明天送达。",
  response_format: "mp3",
});
await writeFile("./reply.mp3", Buffer.from(await speech.arrayBuffer()));
```

> TTS 这段故意不给默认模型：OpenAI 自己的 `/v1/audio/speech` 模型都在关停倒计时里，新项目先确认你选的厂商还提供这个端点。浏览器侧播放把 mp3 交给 `<audio>` 即可；想要对话级延迟，就要换成流式 TTS 或 Realtime 会话。

## 21.3 图像生成：API 一行的事

文生图/图生图（各家 images/generations 端点）是纯集成：`prompt → 返回图片 URL/base64`。OpenAI 现役是 `gpt-image-2.6-sunburst`（精细）/ `gpt-image-2.6-flare`（快速），**只返回 base64**（`data[0].b64_json`）；`gpt-image-1` 已于 2026-10-23 关停，DALL·E 已于 2026-05-12 关停；其他厂商多为 URL 或 base64（2026-11 复核）。

```ts
// multimodal/image.ts —— 文生图，存成 PNG
import OpenAI from "openai";
import { writeFile } from "node:fs/promises";

const media = new OpenAI({ apiKey: process.env.MEDIA_API_KEY, baseURL: process.env.MEDIA_BASE_URL });
const res = await media.images.generate({
  model: process.env.IMAGE_MODEL ?? "gpt-image-2.6-flare", // OpenAI 现役：-flare 快、-sunburst 精细
  prompt: "极简风格的电商物流插画，蓝白配色",
});
const b64 = res.data?.[0]?.b64_json;                 // OpenAI 的 GPT Image 系列只返回 base64
if (!b64) throw new Error("没拿到 b64_json：该厂商可能返回的是 url 字段");
await writeFile("./out.png", Buffer.from(b64, "base64"));
```

（本章四段代码在 `openai@7.5x` 下 `tsc --noEmit` 通过，2026-11 复核；真正运行会产生费用。）

工程考虑：内容安全过滤的报错处理、生成结果缓存（同 prompt 不重复花钱）、前端展示用 `data:image/png;base64,...` 或先存对象存储再给 URL、成本（按图或按图像 token 计费，折合每张约几美分到二十几美分，比文本贵一个量级；智谱 CogView-3-Flash、硅基流动 Kolors 有免费档可练手）。需要工作流编排（多步生成/局部重绘）时看 ComfyUI（自部署开源引擎），那是「AIGC 工程师」垂直岗的领域，应用岗了解即可。

## 21.4 本地模型：知道边界在哪

Ollama（本地跑开源模型：`ollama run qwen3.5:4b`——笔记本也跑得动，同档可选 `gemma4:e4b`；OpenAI 兼容 API `http://localhost:11434/v1`，支持 tools、vision、embeddings 与语音端点，2026-11 复核）在三个场景真有用：**数据不能出域**（内网合规）、**离线**、**零边际成本压测**（评测集反复跑）。但本地小模型与云端旗舰的能力差距显著——**别把「会用 Ollama」当竞争力，把「知道什么任务该本地什么该云端」当竞争力**。你的三件套架构（第 2 章）切本地模型只需改 BASE_URL，这就是分层的红利。

## 21.5 微调：不学，但要有立场（一道面试题）

本课程不教训练与微调——应用岗几乎用不到。你只需要答得出「为什么不用微调解决」，三句话：

1. **微调解决什么**：固化风格/格式/口吻；它**不擅长注入新知识**（事实还是旧的，还可能加重幻觉）
2. **我的替代方案**：知识问题用 RAG（可更新、可溯源）；行为问题用 Prompt/上下文工程（分钟级迭代，微调是天级）
3. **什么时候才轮到它**：固定任务 + 大量标注样本 + 延迟/成本极敏感——那时也是用各家平台的托管微调服务，不是自己从头训

（SFT、LoRA、RLHF 这几个名词的一句话解释见附录 C。）

## ⚠️ 常见坑

1. **在多模态上过度投入**——岗位占比 ~10%，且多数是「API 集成级」要求。选修章节的时间性价比要自己把关。
2. **拿 VLM 输出直接当结构化数据用**——同样是模型输出，该过 Zod 过 Zod（第 4 章原则跨模态成立）。
3. **语音链路忽略打断与延迟**——对话语音体验的决定因素是工程（VAD/打断/流式 TTS），不是模型选型。
4. **「为什么不用微调」答成「微调不好」**——正确姿势是分场景对比 + 给出你的方案与依据（21.5 的三句话）。
5. **照抄旧教程的模型名**——`whisper-1`、`tts-1`、`dall-e-3`、`gpt-image-1` 这些名字在旧资料里到处都是，但已弃用或已关停；写代码前先查一次官方 deprecations 页（2026-11 复核）。
