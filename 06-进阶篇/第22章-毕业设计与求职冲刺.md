## 22.1 项目 3 规格书：多 Agent 调研报告平台

**一句话**：用户输入一个调研主题，平台自动「规划 → 并行检索 → 写作 → 审核」产出一份带引用的报告，全程可视化、可审批、可断点续跑、可算成本。

**架构**（每个模块都是你学过的章节）：


**功能验收**：

```
□ 四类 Agent 各司其职，子任务并行执行（时间线上可见并行分组）
□ 任意时刻刷新页面，任务状态恢复；kill 进程重启后从断点续跑（录屏！）

□ 全链路 Langfuse trace：每步耗时/token/成本可见；按任务出成本账单
□ 10 个任务的完成率评测集 + 失败归因四桶统计（第 15.7）
□ MCP：平台自身暴露 1-2 个工具（如 getReport）供 Claude Code 调用（第 9 章）
□ 权限与注入防线齐全，promptfoo 红队跑过一轮并留报告
```

编排骨架本体——**只导出图，不在文件里直接运行**：

```ts
// server/graph.ts —— 项目 3 编排骨架 v0（mock 工具版；检查点落 SQLite，进程重启也能恢复）
import { END, START, StateGraph, StateSchema, interrupt } from "@langchain/langgraph";
import { SqliteSaver } from "@langchain/langgraph-checkpoint-sqlite";
import { z } from "zod";

// 状态即「任务档案」：checkpointer 会把它的每次变化写进 checkpoints.db
const ResearchState = new StateSchema({
  topic: z.string(),
  subTasks: z.array(z.string()).default(() => []),
  findings: z.array(z.string()).default(() => []),
  draft: z.string().default(""),
  round: z.number().default(0),               // Reflexion 重写轮次计数
  approved: z.boolean().default(false),       // 审核结论写进状态，路由才有依据
});
type S = typeof ResearchState.State;

// ① 规划：拆子任务（第 1 周 mock；第 2 周换成 Plan schema + 真实模型，见 22.1.2）
const plan = async (s: S) => ({
  subTasks: [`${s.topic} 的现状`, `${s.topic} 的竞品`, `${s.topic} 的趋势`],
});

// ② 检索：子任务并行。MOCK_DELAY_MS 模拟检索耗时，方便练习「跑到一半 kill 掉」
const research = async (s: S) => {
  await new Promise((r) => setTimeout(r, Number(process.env.MOCK_DELAY_MS ?? 0)));
  const findings = await Promise.all(s.subTasks.map(async (t) => `[mock] 关于「${t}」的 3 条资料`));
  return { findings };
};

// ③ 写作：汇总成稿
const write = async (s: S) => ({
  draft: `# ${s.topic} 调研报告\n\n${s.findings.join("\n")}`,
  round: s.round + 1,
});

// ④ 审核：interrupt 挂起等人工；恢复时整个节点从头重放，所以 interrupt 之前不要放副作用
const review = async (s: S) => {
  const decision = interrupt({
    question: `报告（第 ${s.round} 稿）是否放行？`,
    preview: s.draft.slice(0, 200),
  }) as { approved: boolean; feedback?: string };
  return decision.approved
    ? { approved: true }
    : { findings: [...s.findings, `[修改意见] ${decision.feedback ?? "补充数据"}`] };
};

// 驳回回写作、放行结束；重写到第 3 稿强制结束（预算熔断思想，第 17 章）
const routeAfterReview = (s: S) => (s.approved || s.round >= 3 ? END : "write");

export const graph = new StateGraph(ResearchState)
  .addNode("plan", plan).addNode("research", research)
  .addNode("write", write).addNode("review", review)
  .addEdge(START, "plan").addEdge("plan", "research").addEdge("research", "write")
  .addEdge("write", "review")
  .addConditionalEdges("review", routeAfterReview, { write: "write", [END]: END })
  .compile({ checkpointer: SqliteSaver.fromConnString("./checkpoints.db") });
```

两条命令的入口——「挂起」和「恢复」故意放在两个进程里：

```ts
// server/cli.ts —— 两条命令演示「挂起 → 进程结束或被 kill → 新进程恢复」
//   pnpm demo:start ["主题"]                          → 打印 threadId，停在 review 等审批，进程退出
//   pnpm demo:resume <threadId> [approve|reject] [意见] → 新进程从 SQLite 读回检查点继续
import { Command } from "@langchain/langgraph";
import { graph } from "./graph";

const [cmd, arg, decision = "approve", feedback] = process.argv.slice(2);

async function report(threadId: string) {
  const snap = await graph.getState({ configurable: { thread_id: threadId } });
  const pending = snap.tasks.flatMap((t) => t.interrupts);
  if (pending.length > 0) {
    console.log("⏸ 已挂起，等待审批：", JSON.stringify(pending[0]?.value));
    console.log(`现在可以关掉/kill 这个进程，之后运行：pnpm demo:resume ${threadId}`);
  } else {
    console.log(`✅ 完成（共 ${snap.values.round} 稿）\n${snap.values.draft}`);
  }
}

if (cmd === "start") {
  const threadId = `task-${Date.now()}`;      // 一个任务 = 一条检查点线（= tasks 表的 id）
  console.log(`threadId: ${threadId}`);
  await graph.invoke({ topic: arg ?? "AI Agent 工程" }, { configurable: { thread_id: threadId } });
  await report(threadId);
} else if (cmd === "resume" && arg) {
  const config = { configurable: { thread_id: arg } };
  const snap = await graph.getState(config);
  if (snap.next.length === 0) {               // MemorySaver 换进程后就是这种「空状态」——这里显式报错而不是静默
    console.error(`找不到可恢复的任务 ${arg}（threadId 拼错了，或任务已结束）`);
    process.exit(1);
  }
  const waitingApproval = snap.tasks.some((t) => t.interrupts.length > 0);
  await graph.invoke(
    waitingApproval
      ? new Command({ resume: { approved: decision === "approve", feedback } }) // 停在审批：注入人的决定
      : null,                                                                   // 跑到一半被 kill：从最后一个检查点接着跑
    config,
  );
  await report(arg);
} else {
  console.log("用法：pnpm demo:start [主题] ｜ pnpm demo:resume <threadId> [approve|reject] [意见]");
}
```

**跑起来**：

```bash
pnpm demo:start "AI Agent 工程"                 # 打印 threadId，停在 review 等审批，进程自己退出
pnpm demo:resume <threadId> reject "补充数据"   # 新进程：驳回 → 写第 2 稿 → 再次挂起
pnpm demo:resume <threadId>                     # 新进程：放行 → 打印报告
```

再练一次真正的「崩溃续跑」：让检索节点慢一点，跑到一半把进程杀掉。

```bash
MOCK_DELAY_MS=8000 pnpm demo:start              # PowerShell：$env:MOCK_DELAY_MS=8000; pnpm demo:start
# 看到 threadId 后几秒内按 Ctrl+C，或另开终端：kill -9 <pid>（PowerShell：Stop-Process -Id <pid> -Force）
pnpm demo:resume <threadId>                     # 从最后一个检查点（plan 之后）接着跑 research，再停在审批
```

（2026-11 复核：以上命令在 Node 24.22 + pnpm 12.18 + `@langchain/langgraph` 1.7.3 + `@langchain/langgraph-checkpoint-sqlite` 1.1.0 下实测通过——start 与 resume 分属不同进程；`kill -9` 在 research 中途杀掉后 resume 续跑成功；目录名含中文和空格同样能跑。）

> **为什么不用第 10 章的 MemorySaver**：它是纯内存的，换一个进程再 `resume`，拿到的是默认空状态（`subTasks: []`、`draft: ""`……），**而且不报错**。所以骨架第 1 周就用 SqliteSaver（单机一个文件）；第 3 周要多实例部署时再换 PostgresSaver。cli.ts 里「`snap.next` 为空就报错退出」也是为了让这类问题当场暴露。
>
> **为什么拆出 cli.ts**：常见的「是不是主模块」判断 ``import.meta.url === `file://${process.argv[1]}` `` 在 Windows（`C:\…` 对 `file:///C:/…`）和含中文/空格的路径（URL 会被百分号编码）下永远不相等，演示代码会静默不执行。图文件只导出、入口单独成文件，就没有这个问题。

**本周验收**：`pnpm typecheck` 0 错误；`pnpm demo:start` 看到挂起 → 进程结束（或中途被 kill）→ 另一个进程 `pnpm demo:resume <threadId>` 恢复成功并打印报告。做到这一步，你就讲得出「断点恢复」的第一层：状态落在哪、恢复时哪个节点会重放、为什么 interrupt 之前不能有副作用。骨架之后每周只加一层（工具 → 持久化 → 观测 → 评测），不要一上来摊大饼。

第 2 周把 research 节点的 mock 换成真子 Agent，大致长这样：

```ts
// server/research.ts —— 第 2 周：把 mock 检索换成真子 Agent（code/src 拷到 server/core/ 后直接复用）
import { runAgent } from "./core/agent/loop";
import { openAIModel } from "./core/lib/model";
import { WORKERS } from "./core/multi/orchestrator";
import { authorize, type SessionContext } from "./core/security/permissions";

export async function researchOne(goal: string, session: SessionContext): Promise<string> {
  const w = WORKERS.researcher;                 // system / tools / model 三隔离（第 11 章）
  const r = await runAgent({
    goal: `${w.system}\n任务简报：${goal}`,
    tools: w.tools,
    model: openAIModel(w.model),                // ChatModel 端口，不是模型名字符串；离线测试换 FakeModel
    maxSteps: 5,
    authorize: (name, args) => authorize(name, args, session), // 默认拒绝 + 资源范围 + 高危转审批（第 18 章）
  });
  if (r.status !== "done") throw new Error(`子任务失败：${r.status}`); // blocked / max_steps / budget_exceeded / no_progress
  return r.answer;
}
```

```ts
// app/api/tasks/[id]/events/route.ts —— SSE：先补发 Last-Event-ID 之后的事件，再每秒轮询新事件
import { and, asc, eq, gt } from "drizzle-orm";
import { db } from "@/db";
import { taskEvents } from "@/db/schema";

export async function GET(req: Request, { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  let lastSeq = Number(req.headers.get("last-event-id") ?? 0); // EventSource 断线重连时浏览器自动带上
  let open = true;
  const enc = new TextEncoder();

  const stream = new ReadableStream<Uint8Array>({
    async start(controller) {
      while (open) {
        const rows = await db.select().from(taskEvents)
          .where(and(eq(taskEvents.taskId, id), gt(taskEvents.seq, lastSeq)))
          .orderBy(asc(taskEvents.seq));
        if (!open) return;                                  // 查询期间客户端已断开
        for (const r of rows) {
          controller.enqueue(enc.encode(`id: ${r.seq}\ndata: ${JSON.stringify({ seq: r.seq, ...r.payload })}\n\n`));
          lastSeq = r.seq;
          const e = r.payload;
          if (e.type === "task.status" && (e.status === "done" || e.status === "failed")) {
            controller.close();                             // 任务结束：主动收尾
            return;
          }
        }
        await new Promise((res) => setTimeout(res, 1000));  // 轮询事件表：跨进程天然成立（图跑在 worker 里也行）
      }
    },
    cancel() { open = false; },                             // 客户端断开
  });

  return new Response(stream, {
    headers: { "Content-Type": "text/event-stream", "Cache-Control": "no-cache, no-transform", Connection: "keep-alive" },
  });
}
```

> 设计取舍：事件先落 `task_events` 表、SSE 路由轮询读出——图跑在别的进程（Inngest worker）也照样推得到，断线重连靠 `seq` 补发，不会丢事件。轮询每秒一次对作品集规模足够；想更实时再换 PostgreSQL 的 `LISTEN/NOTIFY`。`no-transform` 是为了防止中间层（或 Next.js 自托管时的响应压缩）把流攒成一整块再发。

```ts
// server/run-task.ts —— 「跑一个任务」的统一入口：评测、API 路由、CLI 都调它
// 第 1 周：包一层 22.1.1 的骨架，审批自动放行；之后每周只换实现，不换这个签名
import { Command } from "@langchain/langgraph";
import { graph } from "./graph";

export interface TaskOutcome {
  markdown: string;
  citations: { index: number; url: string }[];
  costCny: number;
  latencyMs: number;
  refused: boolean;
}

export async function runTask(topic: string): Promise<TaskOutcome> {
  const config = { configurable: { thread_id: `eval-${Date.now()}-${Math.random().toString(36).slice(2, 8)}` } };
  const t0 = Date.now();
  await graph.invoke({ topic }, config);                                              // 停在 review
```

```ts
// evals/run.ts —— pnpm eval：逐条跑 → 按 expect 断言 → 打印汇总 → 写 evals/report.md（失败用例照样公开）
import { writeFileSync } from "node:fs";
import { runTask, type TaskOutcome } from "../server/run-task";
import { evalTasks, type EvalTask } from "./tasks";

function check(t: EvalTask, o: TaskOutcome): string[] {
  const e = t.expect;
  const fails: string[] = [];
  if (e.shouldRefuse !== undefined && o.refused !== e.shouldRefuse) fails.push(`refused=${o.refused}，期望 ${e.shouldRefuse}`);
  if (e.minCitations !== undefined && o.citations.length < e.minCitations) fails.push(`引用 ${o.citations.length} < ${e.minCitations}`);
  if (e.maxCostCny !== undefined && o.costCny > e.maxCostCny) fails.push(`成本 ¥${o.costCny} > ¥${e.maxCostCny}`);
  if (e.maxLatencyMs !== undefined && o.latencyMs > e.maxLatencyMs) fails.push(`耗时 ${o.latencyMs}ms > ${e.maxLatencyMs}ms`);
  for (const k of e.mustMention ?? []) if (!o.markdown.includes(k)) fails.push(`未提及「${k}」`);
  return fails;
}

const rows: { t: EvalTask; o?: TaskOutcome; fails: string[] }[] = [];
for (const t of evalTasks) {                       // 串行跑：评测要的是可复现，不是快
  try {
    const o = await runTask(t.topic);
    rows.push({ t, o, fails: check(t, o) });
  } catch (err) {
    rows.push({ t, fails: [`运行异常：${err instanceof Error ? err.message : String(err)}`] });
  }
}

const passed = rows.filter((r) => r.fails.length === 0).length;
const lines = [
  `# 评测报告（${new Date().toISOString()}）`, "",
  `通过 ${passed}/${rows.length}`, "",
  "| 任务 | 结果 | 成本 ¥ | 耗时 ms | 失败原因 |", "|---|---|---|---|---|",
  ...rows.map(({ t, o, fails }) =>
    `| ${t.id} ${t.topic} | ${fails.length ? "❌" : "✅"} | ${o ? o.costCny.toFixed(3) : "-"} | ${o?.latencyMs ?? "-"} | ${fails.join("；")} |`),
];
writeFileSync("evals/report.md", lines.join("\n") + "\n");
console.log(lines.join("\n"));
process.exitCode = passed >= 8 ? 0 : 1;            // 门禁：≥8/10 才算过，CI 直接看退出码
```

## ⚠️ 常见坑（毕业项目专属）

1. **先写前端后定契约**：时间线 UI 直接绑死后端内部字段，后端一改全崩——先定 22.1.2 的 SSE 事件表，前后端并行开发。
2. **把 interrupt 放在有副作用的操作之后**：恢复时整个节点从头重放，写文件/发邮件必须幂等——走 `reliability/ledger.ts` 的意图日志 + 幂等键（`runIdempotent`），重启后先 `reconcile()`，否则重跑一次发两封。
3. **用 MemorySaver 演示「断点恢复」**：它是纯内存的，换进程 resume 得到空状态且不报错，演示当场翻车——第 1 周就用 SqliteSaver，多实例部署再换 PostgresSaver；恢复前先 `getState()` 确认确实有检查点。
4. **评测集全是 happy path**：10 个任务里至少放 1 个应拒答、1 个超长、1 个资料冲突——否则完成率 100% 也说明不了什么。
5. **成本看板只算生成不算检索**：embedding/rerank/搜索 API 都是钱；每步 `steps` 表记全，账单才对得上。
6. **追求功能数量**：面试官只往下钻三层——「用了什么/为什么选它/坏了怎么办」。宁可三个模块讲透，不要十个模块都停在第一层。
7. **评测报告只放成功案例**：失败用例和归因是最有说服力的证据；`evals/report.md` 的失败行不要删，写清「为什么失败、下一步改什么」。
8. **pnpm 12 的构建审批没提交**：`pnpm-workspace.yaml`（`allowBuilds`）不进仓库，陌生人或 Docker 里 `pnpm install` 会因 `ERR_PNPM_IGNORED_BUILDS` 失败——README 的「快速开始」要在一台干净机器上真跑一遍。
